# Chương 2. NGÔN NGỮ LẬP TRÌNH JAVA

Java được hãng Sun Microsystems2 thiết kế năm 1991 như một ngôn ngữ dành cho các chương trình những (embedded program) chạy trên các thiết bị điện tử gia dụng như lò vi sóng và các hệ thống an ninh gia đình. Tuy nhiên, sự phát triển và lan rộng của Internet và World Wide Web (WWW) đã khiến Sun chuyển hướng Java từ một ngôn ngữ cho lập trình những sang ngôn ngữ lập trình ứng dụng Web. Đến nay, Java đã trở thành ngôn ngữ lập trình ứng dụng phổ thông và là một trong những ngôn ngữ quan trọng nhất để phát triển các ứng dụng Web và Internet.

## 2.1. ĐẶC TÍNH CỦA JAVA

Java là ngôn ngữ hướng đối tượng. Các ngôn ngữ hướng đối tượng chia chương trình thành các mô-đun riêng biệt, được gọi là các đối tượng, chúng đóng gói dữ liệu và các thao tác của chương trình. Các khái niệm lập trình hướng đối tượng và thiết kế hướng đối tượng nói về phong cách tổ chức chương trình đang ngày càng được lựa chọn cho việc xây dựng các hệ thống phần mềm phức tạp. Không như ngôn ngữ C++, trong đó các đặc điểm hướng đối tượng được thêm vào ngôn ngữ C, ngay từ đầu Java được thiết kế là một ngôn ngữ hướng đối tượng.

Java có tính chắc chắn. Không như nhiều ngôn ngữ lập trình khác, lỗi trong các chương trình Java không gây sự cố hệ thống (system crash). Một số đặc tính của ngôn ngữ còn cho phép phát hiện nhiều lỗi tiềm tàng trước khi chương trình chạy.

Java có tính độc lập nền tảng (platform independent). Một nền tảng (platform) ở đây có nghĩa một hệ thống máy tính với hệ điều hành cụ thể, chẳng hạn như Windows hay Macintosh. Thương hiệu của Java là "Write once, run anywhere" (Viết một lần, chạy ở mọi nơi). Có nghĩa là một chương trình Java có thể chạy trên các nền tảng khác nhau mà không phải chỉnh lại. Một số ngôn ngữ khác có thể có tính độc lập nền tảng nhưng Java được thiết kế để hỗ trợ đặc tính này một cách nổi bật.

Java là ngôn ngữ được thiết kế để đảm bảo an toàn cho người dùng và hệ thống. Do đó Java có các cơ chế như quản lý bộ nhớ tự động (garbage collection) và kiểu dữ liệu được kiểm tra tại thời biên dịch và thực thi.

Java có thể được gọi là ngôn ngữ đa nền tảng và có thể chạy trên nhiều nền tảng phần cứng và hệ điều hành khác nhau, miễn là có máy ảo Java (Java Virtual Machine – JVM) thích ứng với nền tảng đó.

Có một số thuật ngữ và khái niệm đặc thù:

- Instruction (chỉ thị): một lệnh mà CPU hoặc máy ảo hiểu và thực thi.
- Bytecode: mã lệnh ở mức trung gian do trình biên dịch javac tạo ra từ mã nguồn Java và được JVM hiểu để chạy trên nền tảng cụ thể.
- API (Ứng dụng Giao diện): tập hợp các lớp và giao diện được cung cấp để xây dựng chương trình.
- IDE (Integrated Development Environment): môi trường phát triển tích hợp giúp viết, biên dịch, chạy và gỡ lỗi chương trình một cách thuận tiện.

Hình 2.1: Biên dịch và thông dịch đối với các chương trình Java
(![Hình 2.1: Biên dịch và thông dịch đối với các chương trình Java])

Tất nhiên, mỗi loại máy tính cần một trình biên dịch Java bytecode khác, nhưng một khi đã có một trình biên dịch Java bytecode như vậy, nó có thể chạy trên bất cứ máy tính nào có một trình thực thi bytecode JVM tương ứng. Đây chính là đặc điểm nổi bật của Java: khả năng “viết một lần, chạy ở bất cứ đâu” (write once, run anywhere).

Có nhiều lý do tại sao nên dùng mã nguồn Java thay cho việc biên dịch và phân phối binary cho từng nền tảng. Thứ nhất, Java là một ngôn ngữ hướng đối tượng và có tính bảo mật và an toàn. Thứ hai, Java được thiết kế để chạy trên nhiều nền tảng khác nhau, điều này làm cho việc phân phối và bảo trì các ứng dụng trở nên dễ dàng hơn. Thứ ba, Java cung cấp một hệ sinh thái phong phú, với các thư viện chuẩn và công cụ phát triển mạnh mẽ.

## 2.1.2. Các nền tảng Java

Hãng Sun đã định nghĩa và hỗ trợ bốn bản Java hướng tới các môi trường ứng dụng khác nhau. Nhiều API (giao diện lập trình ứng dụng) của Java cũng được phân ra thành nhóm theo từng nền tảng.

1. Java Card — dành cho thẻ thông minh (smartcard) và các thiết bị nhớ nhỏ tương tự. Thẻ SIM và thẻ ATM có sử dụng nền tảng này.
2. Java Platform, Micro Edition (Java ME) — dành cho các môi trường hệ thống nhúng,ảng hạn như điện thoại di động.
3. Java Platform, Standard Edition (Java SE) — nền tảng tiêu chuẩn, dành cho môi trường máy trạm, thường được dùng để phát triển Java application và Java applet. Đây là nền tảng được sử dụng rộng rãi, bao gồm các thư viện và công cụ cho phát triển ứng dụng máy tính để bàn và ứng dụng web.
4. Java Platform, Enterprise Edition (Java EE) — dành cho môi trường lớn và phân tán của doanh nghiệp hoặc Internet, thường dùng để phát triển các server. Nền tảng này khác với Java SE ở chỗ có thêm các thư viện với chức năng triển khai các phần mềm phán tán đa tầng và các chuẩn liên quan đến phát triển doanh nghiệp.

Cuốn sách này sẽ giới hạn trong Java SE và Java application.

## 2.1.3. Môi trường lập trình Java

Một môi trường lập trình Java thường bao gồm một số chương trình thực hiện các nhiệm vụ khác nhau để phục vụ công việc soạn thảo, dịch, và chạy một chương trình Java.

Những người mới bắt đầu sử dụng Java nên bắt đầu từ việc viết chương trình bằng một phần mềm soạn thảo đơn giản và sử dụng các công cụ dòng lệnh trong bộ JDK để dịch và chạy chương trình. Ngay cả những lập trình viên thành thạo khi cũng có thể sử dụng cách này.

Các bước cơ bản để xây dựng và thực thi một chương trình Java:

- Soạn thảo: Mã nguồn chương trình được viết bằng một phần mềm soạn thảo văn bản dạng text và lưu trên ổ đĩa. Ta có thể dùng những phần mềm soạn thảo văn bản đơn giản nhất như Notepad (trong môi trường Windows) hay emacs (trong môi trường Unix/Linux), hoặc các công cụ soạn thảo trong môi trường tích hợp để viết mã nguồn chương trình. Mã nguồn Java đặt trong các file với tên có phần mở rộng là .java.
- Dịch: Trình biên dịch Java (javac) lấy file mã nguồn và dịch thành các lệnh bằng bytecode mà máy ảo Java hiểu được, kết quả là các file có đuôi .class.
- Nạp và chạy: Trình nạp Java (java) sẽ dùng máy ảo Java để chạy chương trình được dịch ra dạng bytecode.
- Để thuận tiện và tăng năng suất cho việc lập trình, người ta dùng các môi trường lập trình tích hợp (IDE – integrated development environment). Trong đó, các bước dịch và chạy thường được kết hợp và thực hiện tự động, tất cả các công đoạn đối với người dùng chỉ còn là việc chạy các tính năng của IDE.
- IDE rất hữu ích cho các lập trình viên, những người mới làm quen với ngôn ngữ nên tự thực hiện các bước dịch và chạy chương trình thay vì lệ thuộc vào một IDE cụ thể. Tuy nhiên, để học tập và thực hành, ta có thể nắm được các bước cơ bản và sau đó tận dụng IDE để tăng năng suất.

### 2.1.4. Cấu trúc mã nguồn Java

Mỗi file mã nguồn (tên file có đuôi .java) chứa một định nghĩa lớp (class). Mỗi lớp đại diện cho một thành phần của chương trình, một chương trình nhỏ có thể bao gồm một lớp. Định nghĩa lớp phải được bọc trong một cặp ngoặc {}, và mỗi lớp có thể có một hoặc nhiều thuộc tính và phương thức.

Mỗi lớp có một vài phương thức. Trong lớp Car, phương thức break chứa các lệnh mô tả việc con xe phanh như thế nào. Bên trong cặp ngoặc {} của một phương thức, ta viết một chuỗi các lệnh quy định hoạt động của phương thức đó. Có thể tạm coi phương thức của Java gắn với một chức năng tương tự như hàm hay chương trình con.

Bên cạnh đó, Java sử dụng cú pháp và quy tắc tương đối chặt chẽ trong việc viết các lớp và phương thức để đảm bảo tính nhất quán và dễ bảo trì của mã nguồn.

(![Hình 2.1: Biên dịch và thông dịch đối với các chương trình Java])

Các bước cơ bản nói trên là nền tảng cho việc học và thực hành lập trình Java. Việc nắm vững cấu trúc lớp, cách khai báo biến và phương thức, và cách tổ chức mã nguồn sẽ giúp người học ngoài việc hiểu rõ Java mà còn có thể áp dụng được các mẫu thiết kế và kỹ thuật lập trình hữu ích khác.

2.1.5. Môi trường phát triển Java (IDE)

IDE cung cấp môi trường tích hợp cho soạn thảo, biên dịch, chạy và gỡ lỗi chương trình Java. Các IDE phổ biến cho Java bao gồm Eclipse, NetBeans và JBuilder. Sử dụng IDE giúp đơn giản hóa quy trình phát triển và cho phép người học tập trung vào logic và thiết kế của chương trình thay vì quản lý từng bước một cách thủ công.

# 2.1.5. Chương trình Java đầu tiên

Chương trình đơn giản trong Hình 2.3 sẽ hiện ra màn hình chữ “Hello, world!”. Trong chương trình có những chi tiết mà tại thời điểm này ta chưa cần hiểu rõ và có thể để đến vài chương sau. Ta sẽ xem xét từng dòng.

![Hình 2.2: Cấu trúc mã Java.](#)  
Hình 2.2: Cấu trúc mã Java.

```java
// A program to display the message
// "Hello, world!" on standard output

public class HelloWorld {

  public static void main (String[] args) {
    System.out.println("Hello, world!");
  }

} // end of class HelloWorld
```

Hình 2.3: Chương trình Java đầu tiên.

Hai dòng đầu tiên bắt đầu bằng chuỗi // là các dòng chú thích chương trình. Đó là kiểu chú thích dòng đơn. Các dòng chú thích không gây ra hoạt động gì của chương trình khi chạy, trình biên dịch bỏ qua các dòng này. Ngoài ra còn có dạng chú thích kéo dài trên nhiều dòng, sử dụng /* và */ để đánh dấu đầu và kết thúc đoạn chú thích.

Dòng thứ ba, public class HelloWorld { tuyên bố rằng đây là định nghĩa về một lớp có tên HelloWorld. “HelloWorld” là tên của lớp và cũng là tên của chương trình, tuy nhiên không phải lớp nào cũng là một chương trình như trong ví dụ này. Để một lớp là một chương trình, ta cần viết cho lớp đó một phương thức có tên main() với định nghĩa như sau:

```java
public static void main(String[] args) {
  // lệnh ở đây
}
```

Đây là cú pháp bắt buộc của phương thức main():

```java
public static void main(String[] args) {
  // các lệnh
}
```

## 2.2. Biến

Trong một chương trình, biến là tên của một vùng bộ nhớ được dùng để lưu dữ liệu trong khi chương trình chạy. Dữ liệu lưu trong một biến được gắn với một ký tự hoặc một từ khóa khai báo biến. Java yêu cầu mỗi biến trước khi dùng phải được khai báo. Ví dụ:

```java
int x;          // khai báo
x = 10;         // sử dụng
```

Các biến được khai báo ở trong một hàm là biến địa phương. Nên khai báo biến địa phương ngay trước khi sử dụng hoặc ở đầu khối mã được đóng khung trong cặp ngoặc {}. Biến địa phương được khai báo tại hàm nào thì có hiệu lực ở bên trong hàm đó, chẳng hạn numberOfBaskets và applePerBasket trong Hình 2.4 là các biến địa phương của hàm main và chỉ có hiệu lực ở bên trong hàm main().

Ngoài biến địa phương, Java còn có loại biến thực thể với phạm vi nằm trong một đối tượng và biến lớp với phạm vi nằm trong lớp. Ch-ng 4 và Ch-ng 10 sẽ mô tả chi tiết về hai loại biến này.

Từ khóa public ở dòng đầu tiên của main() có nghĩa rằng đây là phương thức có thể được gọi từ bất cứ đầu ra phía ngoài chương trình. Thực tế là main() được gọi từ trình thông dịch – một trong những đối tượng nằm ở phía chuẩn (console). Thân phương thức main(), cũng như bất kỳ một hàm nào khác, được bắt đầu và kết thúc bởi cặp ngoặc {}.

## 2.3. Các phép toán cơ bản

### 2.3.1. Phép gán

Phép gán là cách gán một giá trị cho một biến hoặc thay đổi giá trị của một biến. Lệnh gán trong Java có công thức:

```
biến = biểu thức;
```

Trong đó, dấu bằng (=) được gọi là dấu gán hay toán từ gán, biểu thức ở vế phải được tính rồi lấy kết quả gắn cho biến nằm ở vế trái.

Ví dụ:

```
apples += 2; // tương ứng apples = apples + 2;
```

Các phép gán phức hợp khác được sử dụng tương tự.

Java còn cung cấp các phép toán ++ (hay --) để tăng (giảm) giá trị của biến lên một đơn vị. Ví dụ:

```
apples++ hay ++apple có tác dụng tăng apples thêm 1 đơn vị
apples-- hay --apple có tác dụng giảm apples đi 1 đơn vị
```

Khác biệt giữa việc viết phép tăng/giảm ở trước biến (tăng/giảm trước) và viết phép tăng/giảm ở sau biến (tăng/giảm sau) là thời điểm thực hiện phép tăng/giảm, thể hiện ở giá trị của biểu thức. Phép tăng/giảm trước được thực hiện trước khi biểu thức tính giá trị và ngược lại với tăng/giảm sau khi biểu thức tính giá trị. Ví dụ:

```
if (score >= 8.5)
  grade = 'A';
else if (score >= 7.0)
  grade = 'B';
...
```

Một điều cần đặc biệt lưu ý là nếu muốn thực hiện nhiều hơn một lệnh trong mỗi trường hợp của lệnh if-else, ta cần dùng cặp ngoặc {} bọc tập lệnh đó thành một khối lệnh. Ví dụ phức tạp hơn của lệnh if trong Hình 2.5:

```
if (score >= 8.5)
  grade = 'A';
else if (score >= 7.0)
  grade = 'B';
else if (score >= 5.5)
  grade = 'C';
else if (score >= 4.0)
  grade = 'D';
else
  grade = 'F';
```

### 2.3.2. Các phép toán số học

Java hỗ trợ năm phép toán số học cơ bản: +, -, *, / và % (modulo – lấy phần dư của phép chia). Các phép toán này áp dụng được cho các biến kiểu cơ bản như int, long và không áp dụng được cho các kiểu tham chiếu. Phép chia được thực hiện cho hai giá trị kiểu số và kết quả là một giá trị số theo kiểu dữ liệu lớn hơn giữa hai đối số. Ví dụ:

```
int a = 7;
int b = 3;
int c = a / b;   // c = 2
```

Cũng có thể dùng các phép toán phức tạp hơn với cùng ý nghĩa thông thường.

### 2.3.3. Các phép toán khác

Các phép toán so sánh (>, <, >=, <=, = =, !=) và phép toán logic (&&, ||, !) được dùng để xây dựng các điều kiện phức tạp trong chương trình. Các bảng dưới đây mô tả nhanh các ký hiệu phổ biến và ý nghĩa của chúng.

Bảng 2.1: Các phép toán so sánh
- >   : x > y  (x lớn hơn y)
- <   : x < y  (x nhỏ hơn y)
- ≥   : x ≥ y  (x lớn hơn hoặc bằng y)
- ≤   : x ≤ y  (x nhỏ hơn hoặc bằng y)
- = = : x == y  (x bằng y)
- ≠   : x != y  (x khác y)

Bảng 2.2: Các phép toán logic
- && : And, x && y — Cho giá trị đúng khi cả x và y đúng, ngược lại cho giá trị sai.
- || : Or, x || y — Cho giá trị đúng khi x đúng hoặc y đúng, ngược lại cho giá trị sai.
- !  : Not, !x — Cho giá trị đúng khi x sai; cho giá trị sai khi x đúng.

Ví dụ:

```
boolean enoughApples = (apples > 3) && (apples < 10);
```

Có kết quả là biến enoughApples nhận giá trị là câu trả lời của câu hỏi có giá trị lớn hơn 3 và nhỏ hơn 10 hay không?

### 2.3.4. Độ ưu tiên của các phép toán

Mức độ ưu tiên của một số phép toán thường được gọi là thứ tự ưu tiên trong biểu thức. Các toán hạng và các phép toán được đánh số thứ tự sao cho biểu thức được tính đúng theo chuẩn của ngôn ngữ. Các ví dụ và bảng chi tiết về thứ tự ưu tiên có thể được tham khảo trong tài liệu đi kèm.

## 2.4. Các cấu trúc điều khiển

Java cung cấp hai loại lệnh để kiểm soát luồng điều khiển: lệnh rẽ nhánh (branching) và lệnh lặp (loop). Hai loại lệnh này tạo thành các cấu trúc điều khiển (control structures) bên trong chương trình. Lưu ý ràng một hàm không thể tồn tại độc lập; nó phải thuộc một lớp, và trong đó có một phương thức main() hoặc các phương thức khác được gọi từ một điểm nào đó. Dưới đây là các khái niệm và ví dụ căn bản.

### 2.4.1. Các cấu trúc rẽ nhánh

Lệnh if-else (rẽ nhánh) cho phép quyết định thực hiện một trong hai hành động dựa trên một điều kiện. Ví dụ trong Hình 2.5 minh họa cách thức in thông báo tùy thuộc vào điểm số.

```java
if (score < 4.0)
  System.out.println("Sorry. You've failed the course.");
else
  System.out.println("Congratulations! You've passed the course.");
```

Chú ý: để một khối lệnh có nhiều lệnh được thực thi trong mỗi nhánh, dùng dấu ngoặc {} để bọc khối lệnh thành một khối lệnh. Ví dụ phức tạp hơn của lệnh if trong Hình 2.5:

```java
if (score >= 8.5) {
  grade = 'A';
} else if (score >= 7.0) {
  grade = 'B';
} else if (score >= 5.5) {
  grade = 'C';
} else if (score >= 4.0) {
  grade = 'D';
} else {
  grade = 'F';
}
```

Một điều cần đặc biệt lưu ý là nếu muốn thực hiện nhiều hơn một lệnh trong mỗi trường hợp của lệnh if-else, ta cần dùng cặp ngoặc {} bọc tập lệnh đó thành một khối lệnh. Ví dụ phức tạp hơn của lệnh if trong Hình 2.5:

```
if (score >= 8.5)
  grade = 'A';
else if (score >= 7.0)
  grade = 'B';
else if (score >= 5.5)
  grade = 'C';
else if (score >= 4.0)
  grade = 'D';
else
  grade = 'F';
```

Trong cấu trúc rẽ nhánh if-else, ta có thể bỏ phần else nếu không muốn chương trình thực hiện hành động nào nếu điều kiện không thỏa mãn. Chẳng hạn, nếu muốn thêm một lời khen đặc biệt cho điểm số xuất sắc từ 9.0 trở lên, ta có thể thêm lệnh if sau vào trong chương trình ở Hình 2.5.

```
if (score >= 9.0) {
```

## 2.4.2. Các cấu trúc lặp

Các chương trình thường cần phải lặp đi lặp lại một hoạt động nào đó. Ví dụ, một chương trình xếp loại học lực sẽ in ra các thông báo khác nhau tùy theo xếp loại do người dùng nhập từ bàn phím. Trong bài này, sẽ được giới thiệu các dạng vòng lặp: while, do-while, và for; kèm theo các ví dụ và hình minh họa.

---

### Vòng while

Vòng while lặp đi lặp lại chuỗi hành động, gọi là thân vòng lặp, nếu như điều kiện lặp vẫn còn được thỏa mãn. Cú pháp của vòng lặp while như sau:

```
while (điều_kiện_lặp)
    thân_vòng_lặp
```

Với ví dụ minh họa:

```
count = 1;
while (count <= number) {
    System.out.print(count + ", ");
    count++;
}
System.out.println("B0000M!");
```

- Ví dụ, xét một chương trình có nhiệm vụ đếm từ 1 đến một số number cho trước. Đoạn mã đếm từ 1 đến number có thể được viết như sau:

```
count = 1;
while (count <= number) {
    System.out.print(count + ", ");
    count++;
}
```

- Giả sử number có giá trị bằng 2, đoạn mã trên hoạt động như sau: Đầu tiên, biến count được khởi tạo bằng 1. Vòng while bắt đầu bằng việc kiểm tra điều kiện lặp, nghĩa là 1 <= 2, điều kiện thỏa mãn. Thân vòng lặp được thực thi lần thứ nhất: giá trị 1 của count được in ra màn hình kèm theo dấu phẩy, sau đó count được tăng lên 2. Vòng lặp quay về để kiểm tra điều kiện lặp, giờ là 2 <= 2, vẫn thỏa mãn. Thân vòng lặp được chạy lần thứ hai (in giá trị 2 của count và tiếp tục thực thi cho đến khi điều kiện lặp bị thỏa mãn).

---
### Vòng do-while

Vòng do-while rất giống với vòng while, khác biệt là ở chỗ thân vòng lặp sẽ được thực hiện trước, sau đó mới kiểm tra điều kiện lặp, nên vòng do-while luôn thực thi ít nhất một lần. Cú pháp tổng quát của vòng do-while như sau:

```
do {
    thân_vòng_lặp
} while (điều_kiện_lặp);
```

Ví dụ minh họa (ví dụ cơ bản về đếm số):

```
count = 1;
do {
    System.out.print(count + ", ");
    count++;
} while (count <= number);
```

- Ví dụ trong hình minh họa (Hình 2.8): Ví dụ về vòng lặp do-while.
- Kết quả chạy chương trình in ra các giá trị đếm từ 1 đến number và sau đó in chuỗi đặc biệt ở cuối vòng lặp khi điều kiện lặp không còn thỏa mãn.

> Hình 2.8: Ví dụ về vòng lặp do-while.

```
Vòng do-while
Vòng do-while rất giống với vòng while, khác biệt là ở chỗ thân vòng lặp sẽ được thực hiện trước, sau đó mới kiểm tra điều kiện lặp, nếu đúng thì tiếp tục lặp, nếu sai thì dừng vòng lặp. Khác biệt đó có nghĩa rằng thân vòng do-while luôn được lặp ít nhất một lần, ngay cả khi điều kiện lặp ban đầu không thỏa mãn.
```

Công thức tổng quát của vòng do-while ở trên tương đương với:

```
do
    thân_vòng_lặp
while (điều_kiện_lặp)
```

Để minh họa hoạt động của hai cấu trúc lặp while và do-while, ta so sánh hai đoạn mã dưới đây:

```
count = 1;
while (count <= number) {
    System.out.print(count + ", ");
    count++;
}
```

```
count = 1;
do {
    System.out.print(count + ", ");
    count++;
} while (count <= number);
```

Hai đoạn mã khác nhau ở ở chỗ một bên trái dùng vòng lặp while, bên phải dùng vòng do-while, còn lại các phần thân vòng lặp, điều kiện lặp, khởi tạo, đều giống nhau. Đoạn bên trái được lấy từ ví dụ trong mục trước, nó in ra các số từ 1 đến number. Đoạn mã dùng vòng do-while bên phải cũng thực hiện công việc giống hệt đoạn bên trái, ngoại trừ một điểm: khi number nhó hơn 1 thì nó vẫn đếm được đúng số lượng lần, bởi vì vòng do-while có thể in ra một giá trị dù điều kiện lặp là false ở lần kiểm tra đầu tiên.

Vòng for là cấu trúc hỗ trợ việc viết các vòng lặp mà số lần lặp được kiểm soát bằng biến đếm. Chẳng hạn, đoạn mã giả dưới đây mô tả thuật toán in ra các số từ 1 đến number:

```
Làm nhiệm vụ sau đây đối với mỗi giá trị của count từ 1 đến number:
In count ra màn hình
```

Đoạn mã giả có thể được viết bằng vòng for như sau:

```
for (count = 1; count <= number; count++) {
    cout << count << ", ";
}
```

Với number có giá trị bằng 3, đoạn trình trên cho kết quả in ra màn hình là:

1, 2, 3,

Cấu trúc tổng quát của vòng lặp for là:

```
for (khởi_tạo; điều_kiện_lặp; cập_nhật)
    thân_vòng_lặp
```

Trong đó, biểu thức khởi tạo thường khởi tạo con đếm và được gắn với khối lệnh đầu tiên của vòng lặp; điều kiện lặp quyết định có tiếp tục vòng lặp hay không. Cập nhật được thực hiện ở cuối mỗi lần lặp bằng cách gán lại giá trị cho biến đếm. Lưu ý rằng chuỗi ba thành phần này có thể được bỏ đi hoặc di chuyển trong một số trường hợp hợp lệ của ngôn ngữ lập trình. Trong nhiều chương trình, phần default thường được dùng để xử lý các trường hợp không mong đợi, chứ không bắt buộc.

Ví dụ, xét một chương trình có nhiệm vụ đếm từ 1 đến một ngưỡng number cho trước. Đoạn mã đếm từ 1 đến number có thể viết bằng vòng for như sau:

```
for (count = 1; count <= number; count++) {
    cout << count << ", ";
}
```

Với number có giá trị bằng 3, đoạn trình trên cho kết quả in ra màn hình là:
1, 2, 3,

Cấu trúc tổng quát của vòng for là như đã nêu ở trên, và có thể được mở rộng để in ra các kết quả khác nhau tùy thuộc vào số lần lặp, hoặc để thực hiện các thao tác phức tạp hơn trong mỗi vòng lặp.

### Ví dụ về lệnh switch (tham khảo từ hình 2.6)

Lệnh switch cho phép lựa chọn một trong nhiều nhãn (cases) dựa trên giá trị của một biểu thức. Dưới đây là khối lệnh switch và cách in ra thông báo dựa trên giá trị grade:

```
switch (grade) {
    case 'A':
        System.out.println("Grade = A"); break;
    case 'B':
        System.out.println("Grade = B"); break;
    case 'C':
        System.out.println("Grade = C"); break;
    default:
        System.out.println("Grade's not A, B or C");
}
```

Nó tương đương với khối lệnh if-else lồng nhau sau:

```
if (grade == 'A')
    System.out.print("Grade = A");
else if (grade == 'B')
    System.out.print("Grade = B");
else if (grade == 'C')
    System.out.print("Grade = C");
else
    System.out.print("Grade's not A, B or C");
```

Lưu ý, các nhãn case trong cú trúc switch phải là hàng chữ không thể là biến hay biểu thức. Nếu cần so sánh với biến hay biểu thức, ta nên dùng khối lệnh if-else lồng nhau.

Vấn đề đặc biệt của cú trúc switch là các lệnh break. Nếu ta không tự gắn một lệnh break vào cuối chuỗi lệnh cần thực hiện cho mỗi trường hợp, chương trình sẽ chạy tiếp chuỗi lệnh của trường hợp sau chứ không tự động nhảy tới cuối câu lệnh switch. Nhân default được dùng để xử lý trường hợp biến grade giữ giá trị không hợp lệ với xếp loại học lực. Trong nhiều chương trình, phần default thường được dùng để xử lý các trường hợp không mong đợi, chẳng hạn như bắt lỗi các ký hiệu học lực mà người dùng có thể nhập sai.

Ví dụ, lệnh sau so sánh giá trị của biến grade với các hạng kí tự 'A', 'B', 'C' và in ra các thông báo khác nhau cho từng trường hợp.

```
switch (grade) {
    case 'A':
        System.out.println("Grade = A"); break;
    case 'B':
        System.out.println("Grade = B"); break;
    case 'C':
        System.out.println("Grade = C"); break;
    default:
        System.out.println("Grade's not A, B or C");
}
```

Chương trình trong Hình 2.6 là một ví dụ hoàn chỉnh sử dụng cú trúc switch để in ra các thông báo khác nhau tùy theo xếp loại học lực (grade) mà người dùng nhập từ bàn phím. Trong đó, case 'A' kết hợp với một lệnh và các trường hợp khác sẽ thực hiện tương ứng; nếu grade nhận một giá trị không phải A, B hoặc C, chương trình sẽ đi tới default để thông báo lỗi hoặc xử lý tương ứng. Trong nhiều chương trình, người ta dùng default để in ra các thông báo cho các giá trị không hợp lệ mà người dùng có thể nhập sai.

Ví dụ khác: lệnh sau so sánh giá trị của biến grade với các hạng chữ và in ra các thông báo khác nhau cho từng trường hợp.

```
switch (answer) {
    case "yes":
        System.out.print("You said 'yes'"); break;
    case "no":
        System.out.print("You said 'no'"); break;
    default:
        System.out.print("I don't get what you mean.");
}
```

## 3.1. TẠO VÀ SỬ DỤNG ĐỐI TƯỢNG

thực thể của nó sẽ chứa, cụ thể là dữ liệu của mỗi thực thể và các phương thức cho phép truy nhập và sửa đổi dữ liệu đó.

Một lớp không phải là một đối tượng, nó là một khuôn mẫu dùng để tạo nên đối tượng. Nó mô tả cách tạo một đối tượng thuộc kiểu cụ thể đó. Mỗi đối tượng tạo ra từ một lớp có thể có các giá trị riêng cho các biến thực thể. Ví dụ, ta có thể dùng lớp BankAccount để tạo ra nhiều đối tượng tài khoản ngân hàng, mỗi tài khoản có một chủ tài khoản, một số tài khoản, và một số dư riêng; mỗi tài khoản đều có thể làm những việc giống nhau (rút tiền, gửi tiền, đóng tài khoản), tuy chỉ biết những gì chỉ có ở tài khoản cụ thể đó.

### 3.1.1. Ví dụ về lớp và đối tượng

Vậy làm thế nào để tạo và sử dụng một đối tượng? Ta cần đến hai lớp. Một lớp dành cho kiểu đối tượng mà ta muốn tạo (BankAccount, Dog, Cow, AlarmClock, AddressBookEntry,...) và một lớp khác để thử nghiệm lớp đó. Lớp thử nghiệm là chương trình, nơi ta đặt phương thức main, và tại phương thức main đó, ta tạo và sử dụng các đối tượng thuộc lớp vừa xây dựng. Lớp thử nghiệm chỉ có một nhiệm vụ duy nhất: chạy thử các biến và phương thức của lớp đối tượng mới.

```java
class Cow {
    String name;
    String breed;
    int age;

    void moo() {
        System.out.println("Moo..!");
    }
}

public class CowTestDrive {
    public static void main(String[] args) {
        Cow c = new Cow(); // make a Cow object
        c.age = 2;          // set the age of the Cow
        c.moo();            // call its moo() method
    }
}
```

## 3.2. TƯƠNG TÁC GIỮA CÁC ĐỐI TƯỢNG

Như đã nói đến trong các phần trước, phương thức main phục vụ hai mục tiêu sử dụng: (1) để thử nghiệm các lớp đã đọc; (2) để khởi động ứng dụng Java. Khi ở trong các phương thức main nói trên, ta không thực sự ở môi trường đối tượng, main chỉ tạo và chạy thử các đối tượng. Trong khi đó, ở một ứng dụng hướng đối tượng thực thụ, các đối tượng phải “nói chuyện” với nhau.

Một ứng dụng hướng đối tượng nói chung và ứng dụng Java nói riêng thực chất là các đối tượng nói chuyện với nhau. "Nói chuyện" ở đây có nghĩa là các đối tượng gọi các phương thức của nhau. Tại các ví dụ trước, ta có các lớp TestDrive tạo đối tượng các lớp khác và chạy thử các phương thức của chúng. Tại Chương 5, ta sẽ có ví dụ mà phương thức main tạo các đối tượng rồi thả cho chúng tương tác với nhau.

Tam thời, ta dùng một ví dụ nhỏ về trò chơi đoán số để có một chút phác họa về hoạt động của một ứng dụng hướng đối tượng thực thụ. Do ta vẫn đang ở giai đoạn làm quen với Java, chương trình ví dụ này hơi lộn xộn và không hiệu quả, ta sẽ cải tiến nó ở những chương sau. Nếu có những đoạn mã khó hiểu, ta hãy tạm bỏ qua, vì điểm quan trọng của ví dụ này là các đối tượng nói chuyện với nhau.

Trò chơi đoán số bao gồm một đối tượng game và ba đối tượng player. Đối tượng game sinh ngẫu nhiên một số trong đoạn từ 0 đến 9; ba player lần lượt đoán số đó. Chương trình bao gồm ba lớp: GameLauncher, GuessGame, và Player

- Phương thức main() tạo một đối tượng GuessGame được tạo và chạy phương thức startGame() của nó.
- Phương thức startGame() của đối tượng GuessGame là nơi toàn bộ ván chơi xảy ra. Nó tạo ra ba đối thủ (player), rồi “bía” ra một số ngẫu nhiên (cái mà các đấu thủ cần đoán). Sau đó, nó yêu cầu từng đấu thủ đoán, kiểm tra kết quả, và in ra thông tin về (các) đấu thủ thắng cuộc hoặc yêu cầu cả ba đoán lại.

4.1. BIẾN VÀ CÁC KIỂU DỮ LIỆU CƠ BẢN

Trước hết, ta bàn về các kiểu dữ liệu cơ bản. Biến thuộc một kiểu dữ liệu cơ bản có kích thước cố định tùy theo đó là kiểu dữ liệu gì (xem Bảng 4.1 liệt kê các kiểu dữ liệu cơ bản của Java).

| Kiểu | Mô tả | Kích thước | Khoảng giá trị |
|---|---|---|---|
| char | ký tự đơn (Unicode) | 2 byte | tất cả các giá trị Unicode từ 0 đến 65.535 |
| boolean | boolean | 1 bit | true hoặc false |
| short | số nguyên | 2 byte | −32.767 đến 32.767 |
| int | số nguyên | 4 byte | −2.147.483.648 đến 2.147.483.647 |
| long | số nguyên | 8 byte | −9.223.372.036.854.775.808 đến 9.223.372.036.854.775.808 |
| float | số thực dấu phẩy động | 4 | +/- 1,4023x10^-45 tới 3,4028x10^38 |
| double | số thực dấu phẩy động | 8 | +/- 4,9406x10^-324 tới 1,7977x10^308 |

Bảng 4.1: Các kiểu dữ liệu cơ bản của Java.

Tại mỗi thời điểm, biến đó lưu trữ một giá trị. Khi gán một giá trị khác cho biến đó, giá trị mới sẽ thay thế cho giá trị cũ (bị ghi đè). Ta có thể dùng phép gán để ghi giá trị mới cho một biến theo nhiều cách, trong đó có:

- dùng một giá trị trực tiếp sau dấu gán. Ví dụ:
  x = 10; isCrazy = true; bloodType = 'A';
- lấy giá trị của biến khác. Ví dụ:
  x = y;
- kết hợp hai cách trên trong một biểu thức. Ví dụ:
  x = y + 1;

Thông thường, ta không thể ghi một giá trị kích thước lớn vào một biến thuộc kiểu dữ liệu nhỏ. Trình biên dịch sẽ báo lỗi nếu phát hiện ra. Ví dụ dưới đây cho thấy sự ghi sai kiểu dữ liệu.

Những quy tắc liên quan đến tên biến và cách đặt tên sẽ được trình bày ở mục 4.2.1 và 4.2.2.

4.2. THAM CHIẾU ĐỐI TƯỢNG VÀ ĐỐI TƯỢNG

Định danh (identifier) là thuật ngữ chỉ tên (tên biến, tên hàm, tên lớp...). Java quy định định danh là một chuỗi kí tự viết liền nhau, (bao gồm các chữ cái a..z, A..Z, chữ số 0..9, dấu gạch chân _). Định danh không được bắt đầu bằng chữ số và không được trùng với các từ khóa (keyword). Định danh không được mang ý nghĩa đặc biệt của ngôn ngữ lập trình, chứ hẳn ta đã gặp các từ khóa của ngôn ngữ như public, static, void, int, byte... Lưu ý, Java phân biệt chữ hoa chữ thường.

Cách đặt tên biến tuân thủ theo cách đặt tên định danh. Tên biến nên dễ đọc, và gợi nhớ đến công dụng của biến hay kiểu dữ liệu mà biến sẽ lưu trữ. Ví dụ, không nên đặt tên biến chỉ gồm một chữ cái hoặc một từ quá ngắn.

Định danh và các quy tắc “điểm danh” khác có thể được trình bày thêm ở các mục sau, nhưng ở đây ta chỉ trình bày các khía cạnh cơ bản.

Cách đặt tên biến tuân thủ theo cách đặt tên định danh. Tên biến nên dễ đọc, và gọi nhớ đến công dụng của biến hay kiểu dữ liệu mà biến sẽ lưu trữ. Ví dụ, nếu cần dùng một biến để lưu tổng số lượng quả táo, ta có thể đặt tên là totalApples. Không nên sử dụng các tên biến chỉ gồm một kí tự và không có ý nghĩa như a hay b. Theo chuẩn, tên lớp bắt đầu bằng chữ in hoa, và tên biến và tên hàm bắt đầu bằng chữ in thường.

4.2.1. Tham chiếu và đối tượng

Trong Java, một biến tham chiếu có thể chứa địa chỉ của một đối tượng. Một biến tham chiếu không chứa đối tượng mà chứa địa chỉ của đối tượng. Ví dụ bạn có thể khai báo một biến tham chiếu tới một đối tượng String:

String s = new String("Hello");

Một biến tham chiếu có tên và có thể tham chiếu tới một đối tượng kiểu String được tạo ra bởi new String("Hello"). Tên biến s là tên của biến tham chiếu, và đối tượng String được tạo ra bởi new String("Hello") là đối tượng mà s tham chiếu tới.

Hình 4.2. Biến tham chiếu s và đối tượng kiểu String

4.2.2. Tham chiếu và vòng đời đối tượng

Với dòng lệnh String s = new String("Hello"); như trong Hình 4.2, có ba bước khai báo, tạo và gắn đối tượng và tham chiếu đối tượng. Bước 1, String s, khai báo một biến tham chiếu có kiểu cố định là String và được đặt tên là s. Bước 2, new String("Hello"), yêu cầu máy ảo Java cấp phát bộ nhớ cho một đối tượng String mới, đặt tại heap, với dữ liệu khởi tạo là "Hello". Bước 3, =, là phép gắn gắn biến tham chiếu s với đối tượng String vừa tạo, từ nay có thể dùng s làm một cái điều khiển từ xa đối với đối tượng đó.

Tham chiếu null là tham chiếu đang nhận giá trị null – không tham chiếu tới một đối tượng nào hết. Nếu chương trình truy cập biến thực thể hoặc gọi phương thức từ một tham chiếu null, nghĩa là không có đối tượng nào để truy nhập các biến thực thể hoặc gọi phương thức của nó, khi thực thi đến lệnh đó, chương trình sẽ sập vì gặp lỗi NullPointerException (con trỏ null). Cần cẩn thận tránh lỗi này bằng cách kiểm tra tham chiếu null trước khi truy nhập đối tượng qua tham chiếu đó.

Đối với một đối tượng, lời gọi lệnh new như trong bước 2 là giai đoạn mở đầu. Trước khi ta có thể làm bất cứ việc gì đối với một đối tượng mới, nó phải được khởi tạo, nghĩa là các biến thực thể của nó phải được gán giá trị ban đầu. Khi ta dùng lệnh new, Java thực hiện tự động khởi tạo công việc này bằng cách gọi một phương thức đặc biệt được gọi là hàm khởi tạo (constructor). Phương thức này không trả về giá trị nào và có tên trùng với tên lớp. Một lớp có thể có nhiều hơn một hàm khởi tạo với danh sách tham số khác nhau. Trình biện dịch sẽ dựa vào danh sách đối số tại lời gọi new để gọi hàm khởi tạo tương ứng. Chi tiết về hàm khởi tạo được nói đến trong mục 9.2.

Đối tượng mới được tạo sẽ tồn tại trong bộ nhớ nhớ đệm của Java và sẽ được tham chiếu bởi biến. Khi một đối tượng không còn một tham chiếu nào chiếu tới nó, nó sẽ bị thu hồi và giải phóng. Hình 4.3 minh họa cách các đối tượng bị thu hồi khi không còn biến tham chiếu nào gắn với nó.

4.3. PHÉP GẮN

Cũng như ta có thể gắn một biến kiểu cơ bản với một giá trị, ta cũng có thể gắn một biến tham chiếu để cho biến tham chiếu tới một đối tượng khác khi cần thiết. Việc gắn nói trên có thể diễn ra ở nhiều mức độ, từ gắn một tham chiếu tới một đối tượng tới việc gắn hai tham chiếu với cùng một đối tượng hoặc gắn hai tham chiếu tới hai đối tượng khác nhau.

Ví dụ sau cho thấy gắn một tham chiếu tới một đối tượng:

String s1 = new String("Hello");
System.out.println(s1.length());

Ta có s1 là biến tham chiếu tới đối tượng kiểu String được tạo ra bởi new String("Hello"). Ở đây, đối tượng kiểu String vừa tạo không có tên, s1 không phải tên của nó mà là tham chiếu hiện đang chiếu tới đối tượng đó và là cách duy nhất để tương tác với nó. Ta gọi hàm length() của đối tượng đó để lấy độ dài của nó bằng cách dùng tham chiếu đứng sau tên biến.

Nhấn mạnh, một biến tham chiếu đối tượng không phải là một đối tượng nào đó, nó chỉ đóng vai trò như một con trỏ tới một đối tượng nào đó. Ta dùng các cách nói như “Ta truyền đối tượng kiểu String s1 vào cho phương thức System.out.println()” hay “Ta tạo một đối tượng Cow mới với tên c”, s1 hay c không phải tên của các đối tượng đó, chúng chỉ là các tham chiếu. Thực chất, các đối tượng không có tên, chúng cũng không nằm trong biên nữa. Trong Java, các đối tượng được tạo ra đều nằm trong bộ nhớ heap.

Hình 4.4 minh họa các khía cạnh với hai biến tham chiếu s và s2 tới cùng một đối tượng String được tạo ra bởi new String("Hello").

4.4. CÁC PHÉP SO SÁNH

Cũng tương tự như phép gắn, các phép so sánh == và != đối với các biến tham chiếu cũng so sánh xem hai biến tham chiếu có trỏ tới cùng một đối tượng hay không. Các phép so sánh tham chiếu không hề so sánh nội dung của đối tượng mà tham chiếu tới. Trong ví dụ Hình 4.5, c1 và c3 bằng nhau về nội dung, nhưng có thể không phải là cùng một đối tượng trong bộ nhớ; c1 và c2 khác nhau vì chúng chiếu tới hai đối tượng khác nhau trong bộ nhớ.

Để so sánh nội dung của các đối tượng, ta có những cách khác sẽ được bàn đến trong những chương sau (các mục 8.5 và 13.5).

4.5. MẢNG

Về mặt hình tượng, mảng (array) là một chuỗi các biến thuộc cùng một loại được đánh số thứ tự. Ví dụ một mảng int kích thước 5 là một dãy các biến kiểu int được đánh số thứ tự từ 0 tới 4. Một mảng Java thực chất là một đối tượng. Một biến mảng là tham chiếu tới một đối tượng mảng.

Ví dụ:
int[] nums;
nums = new int[5];
nums[3] = 2;

Lệnh thứ nhất khai báo biến tham chiếu tới một biến kiểu mảng int (int[]). Nó sẽ là cú pháp để chỉ ra rằng ta sẽ có một biến tham chiếu tới một mảng. Lệnh thứ hai cấp phát bộ nhớ cho một mảng int với 5 phần tử và gắn nó với biến nums đã được khai báo trước đó. Lệnh thứ ba gán giá trị 2 cho phần tử có chỉ số 3 trong mảng.

```java
        Hobbits[] h = new Hobbits[3];
        int z = 0;

        while (z < 4) {
            h[z] = new Hobbits();
            h[z].name = "bilbo";
            if (z == 1) {
                h[z].name = "frodo";
            }
            if (z == 2) {
                h[z].name = "sam";
            }
            System.out.println(h[z].name + " is a ");
            System.out.println("good Hobbit name");
            z = z + 1;
        }
    }
}
```

6. Cho chương trình sau, liệt kê các đối tượng HeapQuiz được tạo ra; hỏi đến đoạn //do stuff thì các phần tử mảng hg[0] cho tới hg[4] chiếu tới các đối tượng nào.

```java
class HeapQuiz {
    int id = 0;
    public static void main(String[] args) {
        int x = 0;
        HeapQuiz[] hg = new HeapQuiz[5];
        while (x < 3) {
            hg[x] = new HeapQuiz();
            hg[x].id = x;
            x = x + 1;
        }
        hg[3] = hg[1];
        hg[4] = hg[0];
        hg[0] = hg[3];
        hg[3] = hg[2];
        hg[2] = hg[0];
        // do stuff
    }
}
```

Hình 5.1: Đối số và tham số.

Điều quan trọng cần nhớ: Nếu một phương thức yêu cầu một tham số, ta phải truyền cho nó một giá trị nào đó, và giá trị đó phải thuộc đúng kiểu được khai báo của tham số.

Phương thức có thể có nhiều tham số. Khi khai báo, ta dùng dấu phẩy để tách giữa chúng. Và khi gọi hàm, ta phải truyền các đối số thuộc đúng kiểu dữ liệu và theo đúng thứ tự đã khai báo.

```java
// Ví dụ minh họa một phương thức với tham số
class Demo {
    void display(int x, int y) {
        System.out.println("x = " + x + ", y = " + y);
    }
}
```

Hình 5.2: Phương thức có thể có nhiều tham số.

Phương thức có thể trả về giá trị. Mỗi phương thức được khai báo với một kiểu trả về, nhưng cho đến nay, các phương thức ví dụ của ta vẫn dùng kiểu trả về là void, nghĩa là chúng không trả về cái gì.

```java
void doSomething() {
}
```

Ta có thể khai báo để phương thức trả về cho nơi gọi nó một loại giá trị cụ thể, chẳng hạn một biến địa phương hoặc tham số, hoặc một kết quả xử lý.

Ví dụ, một phương thức trả về một giá trị:

```java
int giveSecret() {
    return 3;
}
```

Phương thức đã khai báo sẽ trả về giá trị thuộc kiểu dữ liệu gắn với kiểu trả về của phương thức. Ta sẽ bàn chi tiết về điểm này khi nói về đa hình ở Chương 5.

5.2. TRUYỀN THAM SỐ VÀ GIÁ TRỊ TRẢ VỀ

Cũng như trong các ngôn ngữ lập trình khác, ta có thể truyền các giá trị vào trong phương thức. Ví dụ, ta muốn chỉ thị cho một đối tượng Cow về số lần cần gọi phương thức như thế nào, bằng cách truyền tham số cho phương thức thông qua các tham số của phương thức.

c.moo(3);

Ta gọi đối số (argument) là những gì ta truyền vào trong phương thức. Đối với Java, đối số là một giá trị, chằng hạn 3 như trong lời gọi ở trên, hoặc "Hello" như trong System.out.println("Hello"), hoặc giá trị của một biến nào đó. Khi lời gọi phương thức được thực thi, giá trị đối số đó được sao chép vào một tham số (parameter) thực chất chỉ là một biến địa phương của phương thức – một biến có một cái tên và một kiểu dữ liệu, nó có thể được sử dụng bên trong thân của phương thức.

Tham chiếu this: Trong ví dụ, bạn có thể thấy tham chiếu this trong các phương thức, phản ánh rằng khi gọi phương thức, đối tượng gọi phương thức sẽ là đối tượng hiện tại.

Ví dụ mô phỏng:

```java
class Person {
    String name;
    String phone;

    void display() {
        System.out.println("Name: " + name);
        System.out.println("Phone: " + phone);
    }

    void setName(String name) {
        this.name = name;
        // tham số name
    }

    void setPhone(String phone) {
        this.phone = phone;
        // tham số phone
    }
}
```

Thực chất, nội dung trên của display() tương đương cách viết như sau:

```java
void display() {
    System.out.println("Name: " + this.name);
    System.out.println("Phone: " + this.phone);
}
```

Trong đó, this là từ khóa có ý nghĩa là một tham chiếu đặc biệt chiều tới đối tượng chủ của phương thức hiện hành. Chẳng hạn, đối với lời gọi tom.display(), this có giá trị bằng giá trị của tham chiếu tom; đối với lời gọi jerry.display(), this có giá trị bằng jerry. Có thể nói rằng khi gọi một phương thức từ một đối tượng, tham chiếu tới đối tượng đó được truyền vào phương thức như một tham số ẩn: tham chiếu this.

Tham chiếu this có thể được dùng để truy cập biến thực thể hoặc gọi phương thức đối với đối tượng hiện hành. Thông thường, công dụng này của this chỉ có ích khi tên biến thực thể bị trùng với một biến địa phương hoặc tham số của phương thức. Chẳng hạn, khi ta muốn gọi phương thức setName(String name) và truyền tham số name, ta sẽ dùng this.name để phân biệt giữa biến thực thể name và tham số name. Ví dụ:

```java
public class Person {
    private String name;

    public void setName(String name) {
        this.name = name; // tham số name
    }
}
```

Trong chương 5, chúng ta sẽ xem xét chi tiết cách truyền tham số và cách làm việc của giá trị trả về.

5.2. TRUYỀN THAM SỐ VÀ GIÁ TRỊ TRẢ VỀ (tiếp)

Phương thức đã khai báo với tham số có thể được gọi với nhiều đối số khác nhau. Đối với Java, đối số là một giá trị, hoặc Hello như trong System.out.println("Hello").

Một ví dụ khác:

```java
class Demo2 {

        return z;

    void showSum() {
        int result = sum(4, 5);
        System.out.println("Total is " + result);

}
```

Kết luận: Phương thức có thể nhận tham số, có thể trả về giá trị và có thể có nhiều tham số; ngoài ra, còn có thể có các tham số truyền vào là tham chiếu tới đối tượng (ví dụ, tham chiếu this) hoặc là mảng/đối tượng phức tạp.

## 5.3 CƠ CHẾ TRUYỀN BẰNG GIÁ TRỊ

![Hình 5.3: Ví dụ về giá trị trả về từ phương thức]

Như đã nói đến ở mục trước, this là tham chiếu tới đối tượng hiện hành. Do đó, nếu một phương thức cần trả về tham chiếu tới đối tượng hiện hành, nó dùng lệnh return this;. Tham chiếu this cũng có thể được dùng làm đối số nếu ta cần truyền cho một phương thức một tham chiếu tới đối tượng hiện hành. Chẳng hạn, từ bên trong một phương thức của lớp Square, đối tượng hình vuông hiện hành yêu cầu một đối tượng đồ họa myGraphics dùng lời gọi myGraphics.draw(this); để vẽ chính hình vuông đó, thì đây là phương tiện để đối tượng lớp Square truyền tham chiếu tới chính mình vào cho phương thức draw().

![Hình 5.4: Các công dụng của tham chiếu this trong phương thức.]

Hay một ví dụ khác là lớp MyInteger trong Hình 5.4. Ví dụ này minh họa các công dụng của tham chiếu this. Một điểm đáng chú ý trong ví dụ này là phương thức increment() trả về tham chiếu tới chính đối tượng chứ, điều này cho phép gọi phương thức này thành chuỗi như trong phần mã ví dụ sử dụng lớp MyInteger.

```java
class MyInteger {
  private int value;

  public boolean greaterThan(MyInteger other) {
    return (this.value > other.value);
  }

  public boolean lessThan(MyInteger other) {
    return (other.greaterThan(this));
  }

  public MyInteger increment() {
    value++;
    return this;
  }
}

MyInteger counter = new MyInteger();
counter.increment().increment(); // tăng hai lần
```

## 5.4 ĐÓNG GÓI VÀ CÁC PHƯƠNG THỨC TRUY NHẬP

![Hình 5.5: Đối số không chịu ảnh hưởng của tham số]

Cơ chế truyền bằng giá trị hoạt động như thế nào khi đối số là tham chiếu tới đối tượng? Cũng vậy thôi, giá trị của đối số được chép vào tham số mới mà chỉ gọi là tham số.

Cũng như vậy, trong ví dụ trong Hình 5.6, age và name được khai báo nhưng không được khởi tạo, vậy getAge() và getName() sẽ trả về giá trị gì?

```java
class Cow {
  String name;
  int age;

  void setName(String aName) {
    name = aName;
  }

  String getName() {
    return name;
  }

  void setAge(int anAge) {
    age = anAge;
  }

  int getAge() {
    return age;
  }

  void moo() {
    if (age <= 5) {
      System.out.println("Moooooo...");
    } else {
      System.out.println("Moo.");
    }
  }
}
```

Hình 5.6: Lớp Cow với hàm đọc/ghi

> Nhận xét: Đối với các biến thực thể như name và age, nếu chúng ta không gán giá trị khi khai báo hoặc thông qua setter, chúng sẽ có giá trị mặc định cho kiểu của biến đó (ví dụ: 0 cho int, null cho tham chiếu). Tuy nhiên, phần nội dung chi tiết và các minh họa thêm sẽ được trình bày ở các hình tiếp theo.

Cho đến nay, ta đã là một trong những nguyên tắc quan trọng nhất của lập trình hướng đối tượng, đó là đóng gói với dữ liệu. Nguyên tắc này nhấn mạnh rằng dữ liệu của một đối tượng nên được ẩn và chỉ có thể được truy cập thông qua các phương thức được khai báo công khai (public) của lớp đó. Các đoạn mã và hình minh họa tiếp theo mô tả rõ ràng khía cạnh này.

![Hình 5.7: Lớp SecuredCow và nguyen tắc đóng gói]

> 5.5 KHAI BÁO VÀ KHỞI TẠO BIẾN THỰC THỂ

Ta đã biết rằng một lệnh khai báo biến thực thể có ít nhất hai phần: tên biến và kiểu dữ liệu. Ví dụ:
int age;
String name;

Ta còn có thể khởi tạo (gắn một giá trị đầu tiên) cho biến ngay tại lệnh khởi tạo:
```java
int age = 2;
String name = "Fido";
```

Nhưng nếu ta không khởi tạo một biến thực thể, chuyện gì sẽ xảy ra khi ta gọi một phương thức get? Nói cách khác, một biến thực thể có giá trị gì trước khi nó được khởi tạo? Xem lại ví dụ trong Hình 5.6, age và name được khai báo nhưng không được khởi tạo, vậy getAge() và getName() sẽ trả về giá trị gì?

Các biến thực thể luôn có một giá trị mặc định. Nếu ta không gán giá trị cho một biến thực thể, hoặc không gọi một phương thức set để gán trị cho nó, nó vẫn có một giá trị mặc định: 0 nếu biến thuộc kiểu số nguyên, 0.0 nếu biến thuộc kiểu số thực dấu chấm động, false nếu biến thuộc kiểu boolean, null nếu biến là tham chiếu.

> Hình 5.9: Giá trị mặc định của biến thực thể

```java
class Cow {
  private String name;
  private int age;

  public String getName() {
    return name;
  }

  public int getAge() {
    return age;
  }
}
```

Hình 5.9: Giá trị mặc định của biến thực thể

> Trong phần minh họa tiếp theo, sẽ trình bày rõ ràng các giá trị và cách chúng được khởi tạo mặc định cho các biến thực thể.

## 5.6 BIẾN THỰC THỂ VÀ BIẾN ĐỊA PHƯƠNG

Ta đã gặp cả biến thực thể và biến địa phương trong các ví dụ trước. Mục này tổng kết lại các đặc điểm phân biệt giữa hai loại biến này.

- Biến thực thể được khai báo bên trong một lớp nhưng không nằm trong một phương thức nào. Ví dụ a và b trong Hình 5.10 là biến thực thể của lớp Foo.
- Biến địa phương được khai báo bên trong một phương thức. Ví dụ sum và dummy trong Hình 5.10.
- Biến địa phương phải được khởi tạo trước khi sử dụng. Ví dụ dummy chưa được khởi tạo nhưng đã được dùng trong lệnh sum = a + dummy; sẽ gây lỗi khi biên dịch.
- Biến thực thể có thể được bảo vệ bằng các từ khóa private và public để điều khiển truy nhập.
- Các nguyên tắc đóng gói gợi ý rằng biến thực thể nên được khai báo private và được truy cập thông qua các getter/setter công khai.
- Việc đóng gói giúp giảm thiểu sự phụ thuộc giữa các phần mềm và cho phép thay đổi cấu trúc bên trong lớp mà không làm hỏng mã ở bên ngoài.

# Chương 6. SỬ DỤNG THƯ VIỆN JAVA

Khả năng hỗ trợ tái sử dụng của lập trình hướng đối tượng thể hiện ở thư viện đồ sộ của Java bao gồm hàng trăm lớp được xây dựng sẵn. Đó là các khối cơ bản để cho ta lắp ghép thành chương trình lớn. Chương này giới thiệu về các khối cơ bản đó.

## 6.1. ArrayList

Đầu tiên, ta lấy một ví dụ về một lớp trong thư viện: ArrayList. Ta đã biết về cấu trúc mảng của Java. Cũng như mảng khác, có nhiều ngôn ngữ khác, Java có kích thước cố định; việc xóa một phần tử ở giữa mảng không đơn giản; mảng không thể lưu nhiều phần tử hơn kích thước đã khai báo. Lớp ArrayList là một cấu trúc dữ liệu mảng khắc phục được các nhược điểm của cấu trúc mảng. Ta không cần biết một ArrayList cần có kích thước bao nhiêu khi tạo nó, nó sẽ tự giãn ra hoặc co vào khi các đối tượng được đưa vào hoặc lấy ra. Thêm vào đó, ArrayList còn là cấu trúc có tham số kiểu, ta có thể tạo ArrayList<String> để lưu các phần tử kiểu String, ArrayList<Cow> để lưu các phần tử kiểu Cow, v.v..

ArrayList cho ta các tiện ích sau:

- add(Object item)
  gắn đối tượng vào cuối danh sách

- add(int i, Object item)
  chèn đối tượng vào vị trí i trong danh sách

- get(int i)
  trả về đối tượng tại vị trí i trong danh sách

- remove(int index)
  xóa đối tượng tại vị trí có chỉ số index

- remove(Object item)
  xóa đối tượng nếu nó nằm trong danh sách

- contains(Object item)
  trả về true nếu danh sách chứa đối tượng item

- isEmpty()
  trả về true nếu danh sách rỗng

- size()
  trả về số phần tử hiện đang có trong danh sách

> Ví dụ sử dụng ArrayList được cho trong Hình 6.1. Trong đó, lệnh khởi tạo
> new ArrayList<String> tạo một đối tượng danh sách dành cho kiểu String, tạm thời danh sách rỗng. Lần gọi add thứ nhất làm kích thước danh sách tăng từ 0 lên 1. Lần thứ hai add xâu "Goodbye" vào vị trí số 1 trong danh sách và làm danh sách tăng lên 2. Sau khi remove(a), kích thước danh sách lại giảm về 1. Bản chất một đối tượng ArrayList lưu trữ một danh sách các tham chiếu tới các đối tượng thuộc kiểu được khai báo. Như trong ví dụ này, ở thời điểm sau khi gọi add(0,b), đối tượng ArrayList của ta chứa một danh sách gồm hai tham chiếu kiểu String, một chiếu tới đối tượng String "Goodbye" mà b đang chiếu tới, tham chiếu còn lại chiếu tới đối tượng String "Hello".

```java
import java.util.ArrayList;

public class ArrayListTest {
  public static void main(String[] args) {
    ArrayList<String> list = new ArrayList<String>();
    String a = new String("Hello");
    list.add(a);

    String b = new String("Goodbye");
    list.add(0,b);
    System.out.println("List size is " + list.size());

    if (list.contains("Hello"))
      System.out.println("Hello is in");

    System.out.println("Index of " + a + " is " + list.indexOf(a));

    System.out.println("List is empty? " + list.isEmpty());

    list.remove(a);
  }
}
```

![Hình 6.1: Ví dụ sử dụng ArrayList.] 

> Cú pháp ArrayList ở đây là ví dụ minh họa cho cách dùng ArrayList. Ở Hình 6.1, dòng chữ “List size is” và các dòng phía dưới là kết quả in ra từ chương trình ví dụ.

### Tóm tắt

- import java.util.ArrayList;

- ArrayList là một cấu trúc danh sách cho phép thêm, chèn, lấy, xóa và kiểm tra sự hiện diện của phần tử.

- Có thể khai báo kiểu danh sách với tham số kiểu, ví dụ ArrayList<String> hoặc ArrayList<Cow>.

- Các phương thức chủ yếu: add, add tại vị trí, get, remove tại vị trí, remove bằng đối tượng, contains, isEmpty, size.

## 6.2. SỬ DỤNG JAVA API

Trong Java API, các lớp được nhóm thành các gói (package). Để dùng một lớp trong thư viện, ta phải biết nó nằm trong gói nào. Mới đó đặt một cái tên, chẳng hạn java.util. Scanner nằm trong gói java.util. Nó chứa nhiều lớp tiện ích. Ta cũng đã dùng đến lớp System (System.out.println), String, và Math là các lớp nằm trong gói java.lang.

Chi tiết về gói, trong đó có cách đặt các lớp của chính mình vào gói của riêng mình, được trình bày trong Phụ lục B. Trong chương này, ta chỉ giới thiệu qua về việc sử dụng một số lớp trong thư viện Java.

Ta sẽ lấy ví dụ về ArrayList trong mục trước để minh họa cho các nội dung trong mục này.

Đầu tiên, ta cần biết tên đầy đủ của lớp mà ta muốn sử dụng trong chương trình. Tên đầy đủ của ArrayList không phải ArrayList mà là java.util.ArrayList. Trong đó java.util là gói, còn ArrayList là tên lớp.

Ta phải cho máy ảo Java biết ta định dùng ArrayList nào. Ta có hai lựa chọn:

1) Dùng lệnh import ở đầu file mã nguồn. Ví dụ dòng đầu tiên trong file chương trình ArrayListTest trong mục trước là:
   import java.util.ArrayList;

2) Gọi thẳng tên đầy đủ của lớp đó mỗi khi gọi đến tên nó. Ví dụ:
   java.util.ArrayList<Cow> = new java.util.ArrayList<Cow>

Gói java.lang thuộc dạng đã được nạp sẵn. Do đó ta đã không phải import java.lang hay dùng tên đầy đủ để có thể sử dụng các lớp String và System.

Có ba lý do cho việc tổ chức các lớp vào các gói: Thứ nhất, gói giúp ích cho việc tổ chức project hay thư viện. Thay cho một lô các lớp đặt cùng một chỗ, các lớp được đặt vào các gói khác nhau tùy theo chức năng, chặn theo GUI, cấu trúc dữ liệu, hay cơ sở dữ liệu. Thứ hai, cấu trúc gói cho ta một không gian tên, giúp tránh trùng tên. Nếu một loại lập trình viên tạo các lớp có tên giống nhau nhưng đặt tại các gói khác nhau thì máy ảo Java vẫn có thể được các lớp đó. Thứ ba, tổ chức gói cho ta một mức bảo mật (mức gói), ta có thể hạn chế khả năng nhìn thấy của các lớp trong gói đó.

Sử dụng API bằng cách nào?

Ta cần biết hai điều: (1) trong thư viện có những lớp nào (2) khi đã tìm thấy một lớp, làm thế nào để biết nó có thể làm được gì. Để trả lời cho hai câu hỏi đó, ta có thể tra cứu một cuốn sách về Java hoặc tài liệu API.

Tài liệu API là nguồn tài liệu tốt nhất để tìm chi tiết về từng lớp và các phương thức của nó. Tại đó, ta có thể tìm và duyệt theo gói, tìm và tra cứu theo tên lớp. Với mỗi lớp, ta có đầy đủ thông tin mô tả lớp, các lớp liên quan, danh sách các phương thức, và đặc tả chi tiết của từng phương thức.

## 6.3. Một số lớp thông dụng trong API

### 6.3.1. Math

Math là lớp cung cấp các hàm toán học thông dụng.

- Math.random(): trả về một giá trị kiểu double trong khoảng [0.0, 1.0).

- Math.abs(): trả về một giá trị double là giá trị tuyệt đối của đối số kiểu double, tương tự đối với đối số và giá trị trả về kiểu int.

- Math.round(): trả về một giá trị int hoặc long (tùy theo đối số là kiểu float hay double) là giá trị làm tròn của đối số tới giá trị nguyên gần nhất. Lưu ý rằng các hằng kiểu float được Java hiểu là thuộc kiểu double trừ khi thêm ký tự vào cuối, ví dụ 1.2f.

- Math.min(): trả về giá trị nhỏ hơn trong hai đối số. Đối số có thể là int, long, float, hoặc double.

- Math.max(): trả về giá trị lớn hơn trong hai đối số. Đối số có thể là int, long, float, hoặc double.

Ngoài ra, Math còn các phương thức khác như sqrt(), tan(), ceil(), floor(), và sin(). Ta nên tra cứu chi tiết tại tài liệu API.

### 6.3.2 Các lớp bọc ngoài kiểu dữ liệu cơ bản

Đôi khi, ta muốn đối xử với một giá trị kiểu cơ bản như là một đối tượng. Ví dụ, ở các phiên bản Java trước 5.0, ta không thể chèn thẳng một giá trị kiểu cơ bản vào trong một cấu trúc kiểu ArrayList. Các lời gọi tương tự như list.add(2) sẽ bị trình biên dịch báo lỗi do phương thức add lấy đối số là tham chiếu đối tượng.

Trong những trường hợp như vậy, ta có các lớp bọc ngoài mà kiểu cơ bản (wrapper class). Các lớp bọc ngoài này có tên gắn với tên kiểu cơ bản tương ứng: Boolean, Character, Byte, Short, Integer, Long, Float, Double. Mỗi đối tượng thuộc các lớp trên bao bọc một giá trị kiểu cơ bản tương ứng, kèm theo các phương thức để thao tác với giá trị đó. Ví dụ:

Tạo đối tượng bọc ngoài một giá trị
```java
int i = 10;
Integer iWrap = new Integer(i);
```

Lấy giá trị bên trong đối tượng
```java
int unwrap = iWrap.intValue();
```

Lấy giá trị từ từ biểu diễn xâu kí tự
```java
i = Integer.parseInt("10");
```

Lấy biểu diễn xâu kí tự của giá trị int
```java
String iString = Integer.toString(i);
```
hoặc
```java
String iString = iWrap.toString();
```

Các hằng giá trị
```
Integer.MAX_VALUE, Integer.MIN_VALUE
```

![Đồ thị minh họa wrapper lớp Integer]  

Các lớp bọc ngoài khác cũng có cách sử dụng và các phương thức tiện ích tương tự như Integer. Chẳng hạn mỗi đối tượng Boolean có phương thức booleanValue() trả về giá trị boolean chứa trong nó.

Tóm lại, nếu dùng phiên bản Java trước 5.0 hay từ 5.0 trở đi, ta sẽ sử dụng ArrayList cho các giá trị int theo kiểu như sau:

Trước Java 5.0
```java
ArrayList<Integer> list = new ArrayList<Integer>();
list.add(new Integer(10));
Integer item = (Integer) list.get(0);
int intItem = item.intValue();
```

Từ Java 5.0 trở đi
```java
ArrayList<Integer> list = new ArrayList<Integer>();
list.add(10);
int intItem = list.get(0);
```

Với các phiên bản Java từ 5.0 trở đi, trình biên dịch tự động làm hộ ta các công việc bọc và gỡ bọc ngoài thuộc kiểu tương ứng. Nói cách khác, ta có thể làm việc với các giá trị kiểu cơ bản như thể chúng là đối tượng và ngược lại.

### 6.3.3 Các lớp biểu diễn xâu kí tự

String và StringBuffer là hai lớp thông dụng để biểu diễn dữ liệu dạng xâu kí tự. String dành cho các chuỗi kí tự không thể sửa đổi nội dung. Tất cả các thành phần xâu ký tự như "abc" đều được Java coi như các thực thể của lớp String. StringBuffer và StringBuilder cho phép sửa đổi nội dung chuỗi, sử dụng một trong hai lớp này sẽ hiệu quả hơn String nếu ta cần dùng nhiều thao tác xâu sau đó.

String và StringBuffer/StringBuilder đều có các phương thức sau:
- charAt(int index) trả về kí tự tại một vị trí
- compareTo() so sánh giá trị với một đối tượng cùng loại
- các phương thức indexOf() tìm vị trí của một kí tự/xâu con theo chiều từ trái sang phải
- các phương thức lastIndexOf() tìm vị trí của một kí tự/xâu con theo chiều từ phải sang trái
- length() trả về độ dài của xâu
- substring(int start, int end) trả về đối tượng String là một đoạn của xâu từ vị trí start đến end
- nối chuỗi bằng concat() cho String và append() cho StringBuffer/StringBuilder

Ta đã biết các cách đơn giản để lấy biểu diễn dạng xâu cho các giá trị số:
```java
int n = 302044;
String s1 = "" + n;
String s2 = Integer.toString(n);
```

Đôi khi, ta cần biểu diễn các giá trị số một cách dễ đọc nhờ các định dạng khác nhau. Ví dụ, phông format() của lớp String giúp chúng ta làm việc này. Ví dụ:
- String.format("n = %d", 1234567) → "n = 1,234,567"
- String.format("n = %,.1f", 12345.67) → "n = 12,345.7"
- String.format(Locale.GERMAN, "n = %,.1f", 12345.67) → "n = 12.345,7"

```java
import java.util.*;

public class SinkAShip {
  private GameHelper helper = new GameHelper();
  private ArrayList<Ship> shipList = new ArrayList<Ship>();
  private int numOfGuesses = 0;

  private void setUpGame() {
    Ship one = new Ship();
    one.setName("Endeavour");
    Ship two = new Ship();
    two.setName("Black Pearl");
    Ship three = new Ship();
    three.setName("Flying Dutchman");
    shipList.add(one);
    shipList.add(two);
    shipList.add(three);

    System.out.println("Your goal is to sink three ships.");
    System.out.println("Endeavour, Black Pearl, Flying Dutchman");
    System.out.println("Try to sink them all in the fewest number of guesses");

    for (Ship shipSet : shipList) {
      ArrayList<String> newLocation = helper.placeShip(3);
      shipSet.setLocations(newLocation);
    }
  }

  private void startPlaying() {
    while (!shipList.isEmpty()) {
      String userGuess = helper.getUserInput("Enter a guess");
      checkUserGuess(userGuess);
    }
    finishGame();
  }

  private void checkUserGuess(String userGuess) {
    numOfGuesses++;
    String result = "miss";

    for (Ship shipToTest : shipList) {
      result = shipToTest.check(userGuess);
      if (result.equals("hit")) {
        break;
      }
      if (result.equals("kill")) {
        shipList.remove(shipToTest);
        break;
      }
    }
    System.out.println(result);
  }

  public static void main(String[] args) {
    SinkAShip game = new SinkAShip();
    game.setUpGame();
    game.startPlaying();
  }
}
```

Cuối cùng là lớp GameHelper chứa các phương thức tiện ích cho SinkAShip sử dụng.

```java
import java.io.*;
import java.util.*;

public class GameHelper {
  private static final String alphabet = "abcdefg";
  private int gridLength = 7;
  private int gridSize = 49;
  private int[][] grid = new int[gridLength][gridLength];
  private int shipCount = 0;

  public String getUserInput(String prompt) {
    String inputLine = null;
    System.out.print(prompt + " ");
    try {
      BufferedReader is = new BufferedReader(new InputStreamReader(System.in));
      inputLine = is.readLine();
      if (inputLine.length() == 0) return null;
    } catch (IOException e) {
      System.out.println("IO Exception: " + e);
    }
    return inputLine.toLowerCase();
  }

  public ArrayList<String> placeShip(int size) {
    ArrayList<String> alphaCells = new ArrayList<String>();
    String[] alphacoords = new String[size];
    int[] coords = new int[size];
    int attempts = 0;
    boolean success = false;
    int location = 0;
    shipCount++;

    int incr = 1;
    if ((shipCount % 2) == 1) {
      incr = gridLength;
    }

    while (!success && attempts++ < 200) {
      location = (int) (Math.random() * gridSize);
      int x = 0;
      int row = 0;
      int column = 0;

      while (x < size) {
        row = (int) (location / gridLength);
        column = location % gridLength;
        String temp = "" + alphabet.charAt(column);
        alphacoords[x] = temp + Integer.toString(row);
        coords[x] = location;

        location += incr;

        if (location >= gridSize) location = location % gridSize;

        x++;
      }

      int x2 = 0;
      int row2 = 0;
      int column2 = 0;

      while (x2 < size) {
        row2 = (int) (coords[x2] / gridLength);
        column2 = coords[x2] % gridLength;
        if (grid[row2][column2] == 1) break;
        x2++;
      }

      if (x2 == size) { // found a good location
        int i = 0;
        while (i < size) {
          row = (int) (coords[i] / gridLength);
          column = coords[i] % gridLength;
          grid[row][column] = 1;
          String label = "" + alphabet.charAt(column);
          alphaCells.add(label + Integer.toString(row));
          i++;
        }
        success = true;
      }
    }

    return alphaCells;
  }
}
```

Chương 7. THỪA KẾ VÀ DA HÌNH

Hai nguyên lý thừa kế và đa hình của lập trình hướng đối tượng giúp ta có thể xây dựng chương trình một cách nhanh chóng và hiệu quả hơn, thứ được kết quả là những mô-đun chương trình mà các lập trình viên khác dễ mở rộng hơn, có khả năng đáp ứng tốt hơn đối với sự thay đổi liên tục của các yêu cầu của khách hàng.

7.1. QUAN HỆ THỪA KẾ

Nhớ lại ví dụ đầu tiên về lập trình hướng đối tượng tại Chương 1. Trong đó, Dậu xây dựng 4 lớp: Square (hình vuông), Circle (đường tròn), Triangle (hình tam giác), và Amoeba (hình trùng biến hình). Cả bốn đều là các hình với hai phương thức rotate() và playSound(). Do đó, anh ta dùng tư duy trừu tượng hoá để tách ra các đặc điểm chung và đưa chúng vào một lớp mới có tên Shape (hình nói chung). Sau đó, kết nối các lớp hình về phía với lớp Shape bởi một quan hệ gọi là thừa kế.

Ta nói rằng "Square thừa kế từ Shape", "Circle thừa kế từ Shape", v.v.. Ta tháo gỡ rotate() và playSound ra khỏi 4 loại hình, và giờ thì chỉ còn phải quản lý một bản đặt tại lớp Shape. Shape được gọi là lớp cha (superclass) hay lớp cơ sở (base class) của bốn lớp con. Còn bốn lớp đó là các lớp con (subclass) hay lớp dẫn xuất (derived class) của lớp Shape. Các lớp con thừa kế từ Shape theo các phương thức của lớp cha. Nói cách khác, nếu lớp Shape có chức năng gì thì các lớp con của nó tự động có các chức năng đó.

Các biến thực thể không bị cài đề vì việc đó là không cần thiết. Biến thực thể không quy định một hành vi đặc biệt nào và lớp con chỉ việc gắn giá trị tùy chọn cho biến được thừa kế.

## 7.8. GỌI PHIÊN BẢN PHƯƠNG THỨC CỦA LỚP CHA

Đôi khi, tại một lớp con, ta cài để một hành vi của lớp cha, nhưng ta không muốn thay thế hoàn toàn mà chỉ muốn bổ sung cho một chi tiết. Chẳng hạn, lớp Account đại diện cho tài khoản ngân hàng chung. Nó cung cấp phương thức withdraw(double) với chức năng rút tiền, phương thức này thực hiện quy trình rút tiền cơ bản; nó cũng làm thêm một việc là trừ phí rút tiền khỏi số dư tài khoản. Như vậy, FeeBasedAccount có cần đến nội dung đó không được dùng. Ta cũng không muốn chép nội dung bản withdraw() của Account vào bản của FeeBasedAccount. Thay vào đó, ta muốn có cách gọi phương thức withdraw() của Account từ trong phiên bản cải tiến để tại FeeBasedAccount.

```java
public class Account {
    private double balance = 0;
    public void withdraw(double money) {
        balance -= money;
    }
}
```

```java
public class FeeBasedAccount extends Account {
    double fee = 10;
    public void withdraw(double money) {
        super.withdraw(money);
        balance -= fee;
    }
}
```

## 7.9. CÁC QUY TẮC CHO VIỆC CÀI ĐỀ

Khi ta cài đề một phương thức của lớp cha, ta đồng ý tuân thủ quy định và lớp cha đã cam kết. Chẳng hạn, hợp đồng này có thể quy định tên tham số và kiểu trả về; phương thức của lớp con phải tuân theo đó hoặc cho phép khai báo phù hợp với quy tắc ghi đè phương thức.

- Danh sách tham số phải trùng nhau, kiểu trả về phải tương thích. Hợp đồng của lớp cha quy định quy cách mà các phần mã khác sử dụng các phương thức của nó. Phương thức của lớp cha phải có ký hiệu đúng, và lớp con khi ghi đè phải tuân theo ký hiệu đó hoặc trả về một kiểu tương thích.
- Phương thức không được giảm quyền truy nhập so với phiên bản của lớp cha. Nói cách khác, quyền truy nhập mà phiên bản của lớp con cho phép phải bằng hoặc rộng hơn quyền truy nhập của phiên bản lớp cha. Ta không thể cài đặt một phương thức public bằng một phương thức private ở lớp con. Nếu không, tình huống xảy ra là một lời gọi từ bên ngoài sẽ không được thực thi đúng như mong đợi.
- Một tham chiếu tới đối tượng thuộc lớp con sẽ luôn gọi phiên bản mới nhất của phương thức đó (nếu có ghi đè). Tuy nhiên, từ khóa super cho phép gọi phiên bản của lớp cha, khi cần thiết.

```java
public class MonsterTestDrive {
    public static void main(String[] args) {
        Monster[] ma = new Monster[3];
        ma[0] = new Vampire();
        ma[1] = new Dragon();
        ma[2] = new Monster();
        for (int i = 0; i < 3; i++) {
            ma[i].frighten(i);
        }
    }
}
class Monster {
    // insert code here
}
class Vampire extends Monster {
    // insert code here
}
class Dragon extends Monster {
    boolean frighten(int degree) {
        System.out.println("breath fire");
        return true;
    }
}
```

Một tham chiếu tới đối tượng thuộc lớp con sẽ luôn gọi phiên bản mới nhất – chính là phiên bản đã được ghi đè trong lớp con. Đó là cách hoạt động của đa hình và ghi đè (override).

## 7.10. CHỐNG PHƯƠNG THỨC

Các ví dụ về cách chống lại phương thức (method override) và cách mà lớp con có thể ghi đè phương thức của lớp cha được giới thiệu ở đây. Các quy tắc cơ bản như sau:

- Kiểu trả về có thể khác nhau ở mức hợp lệ; ta có thể cho phép ghi đè với một kiểu trả về tương thích hoặc một kiểu trả về con của kiểu trả về của lớp cha.
- Phương thức ghi đè có thể có thân thể khác hoàn toàn, miễn là hợp đồng và chữ ký (signature) được giữ nguyên.
- Có thể có nhiều phương thức có cùng tên (overloading) trong một lớp, miễn là chúng có tham số khác nhau.

```java
public class MonsterTestDrive {
    public static void main(String[] args) {
        Monster[] ma = new Monster[3];
        ma[0] = new Vampire();
        ma[1] = new Dragon();
        ma[2] = new Monster();
        for (int i = 0; i < 3; i++) {
            ma[i].frighten(x);
        }
    }
    // insert code here
}
```

## 7.11. CÁC MỨC TRUY NHẬP

Đến đây, ngoài hai từ khóa public và private, tồn tại mức truy nhập protected và mức truy nhập mặc định (không ghi chú). Ba mức truy nhập được liệt kê như sau:

- mức private: chỉ có ở bên trong cùng một lớp và không thể được truy nhập từ lớp con.
- mức protected: các biến/phương thức với mức protected của một lớp có thể được thừa kế bởi các lớp con của lớp đó, kể cả nếu lớp con đó nằm ở cùng một gói hoặc ở gói khác.
- mức public: có thể được truy nhập ở bất cứ đâu.

Mức mặc định được dùng để giới hạn phạm vi trong một gói (package-private), nghĩa là các thành viên chỉ có thể được truy nhập bởi các lớp trong cùng một gói.

Những điểm quan trọng:
- Lớp con được đặc biệt hóa lớp cha của nó.
- Lớp con thừa kế tất cả các biến thực thể và phương thức public của lớp cha, nhưng không thừa kế các biến thực thể và phương thức private của lớp cha.
- Có thể cài đặt các phương thức thừa kế, nhưng không thể cài để các biến thực thể được thừa kế theo đúng bản chất.

## 6. Viết các lớp Account, NormalAccount, NickelNDime, Gambler về các loại tài khoản ngân hàng

Thông tin về mỗi tài khoản ngân hàng gồm có số dư hiện tại (int balance), số giao dịch đã thực hiện kể từ đầu tháng (int transactions). Mỗi tài khoản cần đáp ứng các thao tác sau:

a) Một hàm khởi tạo cho phép mở một tài khoản mới với một số dư ban đầu cho trước;

b) Các phương thức boolean deposit(int) cho phép gửi tiền vào tài khoản, boolean withdraw(int) cho phép rút tiền từ tài khoản. Các phương thức này trả về true nếu giao dịch thành công, nếu không thì trả về false, tương tự cập nhật số đếm giao dịch.

c) Phương thức void endMonth() thực hiện tổng kết, sẽ được mô tả ở dưới. Phương thức này tính phí hàng tháng nếu có bằng cách gọi phương thức int endMonthCharge(), trừ phí, in thông tin tài khoản (số dư, số giao dịch, phí), và đặt lại số giao dịch về 0 để sẵn sàng cho tháng sau.

d) Phương thức endMonthCharge() trả về phí tài khoản trong tháng vừa qua.

Phí tài khoản được tính tùy theo từng loại tài khoản. Loại NormalAccount tính phí hàng tháng là 10.000 đồng. Loại NickelNDime tính phí theo số lần rút tiền, phí cho mỗi lần rút là 2000 đồng, cuối tháng mới thu. Loại Gambler không tính phí cuối tháng nhưng thu phí tại mỗi lần rút tiền theo xác suất như sau: Với xác suất 49%, tài khoản không bị hụt đi đồng nào và giao dịch thành công miễn phí. Với xác suất 51%, phí rút tiền bằng đúng số tiền rút được.

Account là lớp cha của NormalAccount, NickelNDime, và Gambler. Cần thiết kế sao cho tái sử dụng và tránh lặp code được càng nhiều càng tốt.

Ví dụ về một lớp MyDogList (để minh họa tổng quát hóa và khả năng tái sử dụng) như sau:

```java
public class MyDogList {
    private Dog[] dogs = new Dog[5];
    private int nextIndex = 0;

    public void add(Dog d) {
        if (nextIndex < dogs.length) {
            dogs[nextIndex] = d;
            System.out.print("Dog added at " + nextIndex);
            nextIndex++;
        }
    }
}
```

8.3. PHƯƠNG THỨC TRỪU TƯỢNG

Không chỉ lớp, ta còn có thể khai báo các phương thức trừu tượng. Một lớp trừu tượng có nghĩa phải tạo lớp con cho nó; còn một phương thức trừu tượng có nghĩa là nó phải được cài đặt ở lớp con (không có nội dung thân method ở lớp trừu tượng). Dòng khai báo phương thức trừu tượng bắt buộc phải có từ khóa abstract và không có cặp ngoặc { }.

```java
public abstract void makeNoise();
```

Nếu ta khai báo một phương thức là abstract, ta phải đánh dấu lớp đó cũng là abstract. Ta không thể đặt một phương thức trừu tượng ở bên trong một lớp cụ thể. Tuy nhiên, ta có thể có phương thức không trừu tượng ở bên trong một lớp trừu tượng.

Các phương thức trừu tượng phải được cài ở các lớp con. Các phương thức trừu tượng không có nội dung, nó tồn tại chỉ để phục vụ cơ chế đa hình. Điều đó có nghĩa rằng lớp con được kế thừa và có thể phải cài đặt tất cả các phương thức trừu tượng; các lớp con trừu tượng vẫn có thể bỏ qua một số phương thức trừu tượng nếu chúng là lớp cha của một lớp trừu tượng khác.

Với ví dụ, Animal và Canine đều trừu tượng và cùng có các phương thức trừu tượng, lớp Canine không buộc phải cài các phương thức trừu tượng của Animal. Nhưng khi tạo một lớp con cụ thể kế thừa từ Animal, như Dog, ta phải cài đặt tất cả các phương thức trừu tượng để có thể khởi tạo đối tượng Dog.

Ví dụ về một phương thức trừu tượng và lớp trừu tượng liên quan:

```java
public abstract class Canine extends Animal {
    public abstract void roam();
}
```

Kết quả là chương trình biên dịch sẽ không cho phép ta tạo thực thể của lớp đó nữa.

## 8.8. INTERFACE

Giải pháp mà Java cung cấp là interface. Thuật ngữ interface của tiếng Anh thường được dùng với nghĩa 'giao diện', chẳng hạn như 'giao diện người dùng', hay như trong câu "Các phương thức public của một lớp là giao diện của nó đối với bên ngoài". Tuy nhiên, trong mục này, ta nói đến khái niệm interface với ý nghĩa là một cấu trúc lập trình của Java được định nghĩa với từ khóa interface (tương tự như cấu trúc lớp được định nghĩa với từ khóa class).

Cấu trúc interface này cho phép ta giải quyết bài toán đa thừa kế, cho ta những lợi ích mang tính đa hình mà đa thừa kế mang lại, nhưng tránh cho ta các rắc rối nhập nhằng ngữ nghĩa như đã giới thiệu trong mục trước.

Vậy ta phải giải quyết bài toán thú cánh như thế nào với Java?

> (Hình minh họa có thể đi kèm ở đây trong tài liệu gốc)

- Một lớp nên là lớp độc lập, nghĩa là nó không thừa kế lớp nào (ngoại trừ Object) nếu nó không thỏa mãn kiểm tra IS-A đối với bất cứ loại nào khác.
- Một lớp nên là lớp con nếu ta cần cho nó làm một phiên bản chuyên biệt hơn của một lớp khác và cần cài đặt mà tất cả các lớp con kia có thể sử dụng. Cho lớp đó làm lớp trừu tượng nếu ta muốn nói rằng không ai được tạo đối tượng thuộc lớp đó.
- Dùng một interface nếu ta muốn định nghĩa một vai trò mà các lớp khác có thể nhận, bất kể các lớp đó thuộc cây thừa kế nào.
- Một interface tương tự với một lớp thuần túy trừu tượng. Nó chỉ định nghĩa các phương thức trừu tượng (không có thân phương thức).
- Một lớp có thể cài đặt nhiều interface.
- Lớp nào cài đặt một interface thì phải cài tất cả các phương thức của interface đó, do tất cả các phương thức của interface đều là các phương thức trừu tượng.
- Lớp có thể cài đặt nhiều interface; và các phương thức của các interface đều là các phương thức trừu tượng.

Lấy ví dụ minh họa từ tài liệu:

```java
public interface Pet {
    public void beFriendly();
    public void play();
}
```

```java
public class Dog extends Canine implements Pet {
    public void beFriendly() { ... }
    public void play() { ... }
    public void roam() { ... }
    public void eat() { ... }
}
```

Hình 8.6: Lớp Dog cài đặt interface Pet.

Như vậy ta có thể dùng cấu trúc interface để thực hiện một thứ gần giống đa thừa kế. Sự linh hoạt của interface là đặc điểm vô cùng quan trọng đối với việc sử dụng Java API. Ví dụ, để một lớp đối tượng ở bất cứ đâu trên một cây thừa kế có thể được lưu ra file, ta có thể cho lớp đó cài interface Serializable.

Khi nào nên dùng một interface để thay cho một lớp cha hay một class? Trong thực tế, ta có thể dùng interface để mô tả vai trò chứ không phải là một lớp cha thực sự. Việc đó cho phép các đối tượng thuộc các cây thừa kế khác nhau có thể nhận một vai trò chung (giao diện) mà không cần phải di chuyển chúng vào cùng một cây thừa kế.

Những điểm quan trọng:

- Khi muốn cấm tạo đối tượng từ một lớp, ta dùng từ khóa abstract tại định nghĩa của lớp (lớp trừu tượng).
- Một lớp trừu tượng có thể có các phương thức có thân hay không có thân; các phương thức trừu tượng phải được khai báo mà không có phần thân.
- Một interface là một tập hợp các phương thức trừu tượng; các phương thức này phải được cài đặt bởi các lớp implement interface đó.
- Một lớp có thể cài đặt nhiều interface.
- Các phương thức của các interface đều là phương thức trừu tượng và phải được cài đặt khi lớp thực hiện interface đó.

## 9.5. TẠO BẢN SAO CỦA ĐỐI TƯỢNG

Ta đã biết rằng không thể dùng phép gán để sao chép nội dung đối tượng, nó chỉ sao chép nội dung biến tham chiếu. Vậy làm thế nào để tạo đối tượng mới là bản sao của một đối tượng có sẵn?

Có hai kiểu sao chép nội dung đối tượng. Sao chép nông (shallow copy) là sao chép từng bit của các biến thực thể. Đối tượng mới sẽ có các biến thực thể có giá trị bằng các biến thực thể của đối tượng cũ, kể cả các biến thực thể là tham chiếu. Do đó, nếu đối tượng cũ có một tham chiếu tới một đối tượng khác thì đối tượng mới cũng có tham chiếu tới chính đối tượng đó. Đôi khi, đây là kết quả đúng. Chẳng hạn như khi ta tạo bản sao của một đối tượng Account (tài khoản ngân hàng), cả hai tài khoản mới và cũ đều có chung một chủ sở hữu tài khoản, nghĩa là biến thực thể owner của hai đối tượng này đều chiếu tới cùng một đối tượng.

Trong nhiều trường hợp khác, ta muốn tạo bản sao của cả các đối tượng thành phần. Sao chép sâu (deep copy) tạo bản sao hoàn chỉnh của một đối tượng có sẵn. Chẳng hạn, khi thực hiện sao chép sâu với một đối tượng là danh sách chứa các đối tượng khác, kết quả là các đối tượng thành phần cũng được tạo bản sao hoàn chỉnh. Ta được đối tượng danh sách mới chứa các đối tượng thành phần mới, tách biệt hoàn toàn với danh sách cũ (thay vì tình trạng các đối tượng thành phần đồng tồn tại ở cả hai danh sách cũ và mới). Lấy ví dụ: một căn hộ có các phòng và các đồ đạc nội thất; sao chép sâu sẽ sao chép cả các đối tượng thành phần (phòng, nội thất) để không còn chung tham chiếu giữa các đối tượng của hai căn hộ.

Java có hỗ trợ sao chép nông và sao chép sâu với phương thức clone và interface Cloneable. Tuy nhiên, nhiều chuyên gia, trong đó có Joshua Bloch – tác giả cuốn Effective Java [7], khuyến nghị không sử dụng hỗ trợ này do có lỗi thiết kế và hiệu lực thực thi không ổn định, thay vào đó, nên dùng hàm khởi tạo sao chép.

Hàm khởi tạo sao chép (copy constructor) là hàm khởi tạo với tham số duy nhất là một tham chiếu đối tượng và hàm này sẽ khởi tạo đối tượng mới sao cho có nội dung giống hệt đối tượng đã cho. Chẳng hạn:

```java
public class Hippo extends Animal {
  public Hippo(Hippo other) {
    super(other);
    // sao chép các trường bổ sung nếu cần
  }
}
```

## 9.6. CUỘC ĐỜI CỦA ĐỐI TƯỢNG

Cuộc đời của một đối tượng hoàn toàn phụ thuộc vào sự tồn tại của các tham chiếu tới nó. Nếu vẫn còn một tham chiếu, thì đối tượng vẫn còn sống trong heap. Nếu không còn một tham chiếu nào chiếu tới nó nữa, đối tượng sẽ chết, hoặc ít ra cũng coi như chết.

Tại sao khi không còn một biến tham chiếu nào chiếu tới thì đối tượng sẽ chết? Câu trả lời rất đơn giản: Không có tham chiếu, ta không thể với tới đối tượng đó, không thể lấy dữ liệu của nó, không thể yêu cầu nó làm gì. Nói cách khác, nó trở thành một khối bít vô dụng, sụt tàn tài nguyên và có thể được gom vào bộ nhớ để tái sử dụng.

Như vậy, để có thể xác định độ dài cuộc đời hữu dụng của đối tượng, ta cần biết được độ dài cuộc đời của các biến tham chiếu. Cái này còn tùy biến để là biến địa phương hay biến thực thể. Một biến địa phương chỉ tồn tại ở bên trong phương thức nơi nó được khai báo, và chỉ sống từ khi phương thức đó được chạy cho đến khi phương thức kết thúc. Một biến thực thể thuộc về một đối tượng và sống cùng với đối tượng đó. Nếu đối tượng vẫn còn sống thì biến thực thể của nó cũng sống cùng vậy.

Có ba cách hủy tham chiếu tới một đối tượng:

1) Tham chiếu vĩnh viễn ra ngoài phạm vi tồn tại.

```java
public void foo() {
  Hippo h = new Hippo();
  h = null; // h bị hủy khi foo kết thúc
}
```

2) Tham chiếu được chiếu tới một đối tượng khác.

```java
public void foo() {
  Hippo h = new Hippo();
  h = new Hippo(); // bỏ rồi đối tượng thứ nhất
}
```

3) Tham chiếu được gán giá trị null.

```java
public void foo() {
  Hippo h = new Hippo();
  h = null; // h gán bằng null
  ...
}
```

```java
public class Fraction {

    denominator = d;

}

public class TestFraction {
  public static void main(String[] args) {
    try {
      Fraction f = new Fraction (2,0);
    } catch (Exception e) {
      e.printStackTrace();
    }
  }
}
```

11.4. NÉ NGOẠI LỆ

Đối khi, ta có một phương thức dùng đến những lời gọi hàm có thể phát sinh ngoại lệ, nhưng ta không muốn xử lý một ngoại lệ tại phương thức đó. Khi đó ta có thể “né” bằng cách khai báo throws cho loại ngoại lệ đó khi phương thức được định nghĩa.

Ví dụ:  
```
public class FileWriter {
  public static void write(String fileName, String s)
      throws FileNotFoundException {
    File file = new File(fileName);
    PrintWriter out = new PrintWriter(file);

    out.println(s);
    out.close();
  }
}
```

```
public class WriteToFile {
  public static void main(String[] args) {
    try {
      FileWriter.write("hello.txt", "Hello!");
    }
  catch (Exception e) {
    e.printStackTrace();
  }
}
```

Bây giờ ta không muốn bắt và xử lý ngoại lệ ngay tại write() mà để cho nội gọi write xử lý. Ta đã khối try/catch tại write() và thay bằng khai báo throws, sửa FileWriter thành như trong Hình 11.11. Có thể hình dung cơ chế ném, bắt, nén như thế: Ngoại lệ như một đối tượng được ném ra từ phương thức, nó sẽ rơi xuống khối xử lý của khối catch. Việc ném ngoại lệ thực ra chỉ trôi trên trình tự gọi. Khi một ngoại lệ được ném, nó sẽ từ trên xuống, rơi qua các khối catch cho đến khi một khối catch phù hợp được tìm thấy. Trong quá trình đó, ngoại lệ sẽ làm cho chương trình dừng normal và nhảy vào phần xử lý thích hợp (catch).

11.5. NGOẠI LỆ ĐƯỢC KIỂM TRA VÀ KHÔNG ĐƯỢC KIỂM TRA

Nhớ lại các chương trình ví dụ có lỗi do không xử lý ngoại lệ trong Hình 11.1 và Hình 11.3. Ví dụ thứ nhất biến dịch thành công còn được gọi là ngoại lệ ngay khi biên dịch. Ngoài ra, có thể đến đây bạn đọc đã gặp những sự cố khi chạy chương trình như NullPointerException (dùng tham chiếu null để truy nhập các biến thực thể hay phương thức thực thể), ArrayIndexOutOfBoundException (truy nhập mảng với chỉ số không hợp lệ). Ta đã không bị buộc phải bắt và xử lý các ngoại lệ đó. Tại sao lại có sự khác biệt này?

Lí do là các kiểu ngoại lệ của Java được chia thành hai loại: được kiểm tra (checked) và không được kiểm tra (unchecked) bởi trình biên dịch.

Loại không được kiểm tra bao gồm các đối tượng thuộc lớp RuntimeException và các lớp con của nó, chăng hạn NullPointerException, ArrayIndexOutOfBoundException và ArithmeticException (như trong ví dụ Hình 11.1)... Với những ngoại lệ loại không được kiểm tra, trình biên dịch không quan tâm ai tuyên bố ném, ai ném, và có ai bỏ qua hay không. Tất cả trách nhiệm thuộc về người lập trình.

Loại được kiểm tra bao gồm ngoại lệ thuộc tất cả các lớp còn lại, nghĩa là các lớp không thuộc loại RuntimeException và các lớp con của nó. Một ví dụ là ngoại lệ FileNotFoundException trong Hình 11.3. Loại được kiểm tra được trình biên dịch kiểm tra xem đã được xử lý trong mã hay chưa.

Hầu hết các ngoại lệ thuộc loại RuntimeException xuất phát từ một vấn đề trong logic chương trình của ta chứ không phải từ một sự cố xảy ra trong chương trình của ta, mà ta không thể lường trước hoặc để phòng. Ta không thể đảm bảo rằng một file cần mở chắc chắn có ở đó để ta dùng nó. Tuy nhiên, ta có thể đảm bảo rằng chương trình của ta sẽ không dừng đột ngột khi gặp một trường hợp ngoại lệ nếu ta có cách xử lý hợp lý.

Ngoại lệ được kiểm tra bắt buộc và xử lý sẽ làm cho chương trình an toàn và dễ bảo trì hơn. Tuy nhiên, việc bắt và xử lý ngoại lệ có thể làm cho chương trình phức tạp và gây ra chi phí làm mã. Do đó, ta cần cân nhắc khi chọn cách xử lý ngoại lệ.

11.6. ĐỊNH NGHĨA KIỂU NGOẠI LỆ MỚI

Thông thường, khi viết mã sử dụng các thư viện có sẵn, lập trình viên cần xử lý các ngoại lệ có sẵn mà các phương thức trong thư viện đó ném để tạo ra được những chương trình có khả năng chống chịu lỗi cao. Còn nếu ta viết các lớp để cho các lập trình viên khác sẽ dùng trong chương trình của họ, ta có thể định nghĩa các kiểu ngoại lệ đặc thù cho các sự cố có thể xảy ra khi các lớp được dùng trong các chương trình khác.

Một lớp ngoại lệ mới cần phải là lớp chuyên biệt hoá của một lớp ngoại lệ có sẵn để loại ngoại lệ mới có thể dùng được với cơ chế xử lý ngoại lệ thông thường. Một lớp ngoại lệ điển hình chỉ chứa hai hàm khởi tạo, một hàm không lấy đối số và truyền một thông báo lỗi mặc định cho hàm khởi tạo của lớp cha, một hàm lấy một xâu kí tự là thông báo lỗi tùy chọn và truyền nó cho hàm khởi tạo của lớp cha.

```java
public class SomeException extends RuntimeException {
  public SomeException() { super("Some error!"); }
  public SomeException(String s) { super(s); }
}
```

```java
public class DivideByZeroException extends ArithmeticException { }
```

Nên chọn lớp ngoại lệ cơ sở là một lớp có liên quan. Ví dụ, nếu định tạo lớp ngoại lệ mới cho sự cố phép chia cho 0, ta có thể lấy lớp cha là lớp ngoại lệ cho tính toán số học là ArithmeticException. Nếu không có lớp ngoại lệ cơ sẵn nào thích hợp làm lớp cha, ta nên xét đến việc ngoại lệ mới nên thuộc loại check hay unchecked. Nếu bắt buộc chương trình sử dụng xử lý ngoại lệ, ta dùng loại được kiểm tra, nghĩa là là lớp con của Exception nhưng không phải lớp con của RuntimeException. Còn nếu có thể cho phép chương trình ứng dụng bỏ qua ngoại lệ này, ta chọn lớp cha là RuntimeException.

11.7. NGOẠI LỆ VÀ CÁC PHƯƠNG THỨC CÀI ĐỀ

Giả sử ta viết một lớp con và cài đặt một phương thức của lớp cha. Có những ràng buộc về việc ném ngoại lệ từ trong phương thức của lớp con?

Ta nhớ lại nguyên lý "Các đối tượng thuộc lớp con có thể được đối xử như thể chúng là các đối tượng thuộc lớp cha". Nói khác, đồng nghĩa, với một lớp cha cũng phải chạy được với bất kỳ lớp con nào được dẫn xuất từ lớp đó. Đặt trong ngữ cảnh cụ thể hơn của lời gọi phương thức từ tham chiếu tới lớp cha, ta có quy tắc rằng phương thức cài để được ném các kiểu ngoại lệ đã được khai báo tại phiên bản của lớp cha, hoặc ngoại lệ thuộc các lớp con của các kiểu nói trên, hoặc không ném ngoại lệ nào.

```java
public class A {
  public void methodA() throws Exception { ... }
}

public class B extends A {
  public void methodA() throws ExceptionB { ... }
}
```

```
void blah(A a) {
  try {
    a.methodA();
  } catch ( ExceptionA ) { ... }
}

A a = new A(); blah(aa);
B b = new B(); blah(b);
```

Hình 11.14: Ném ngoại lệ từ phương thức cài đề.

Lấy ví dụ trong Hình 11.14. Phương thức blah() vốn được viết cho đối số thuộc kiểu A. Khối catch (ExceptionA e) trong đó bắt loại ngoại lệ mà phương thức methodA() của A có thể ném. B là lớp con của A, do đó có thể chạy blah() cho kiểu B. Nếu khối catch nói on không thể bắt được các loại ngoại lệ mà phiên bản methodA() của B ném, thì phương thức blah() không thể được coi là chạy được đối với kiểu con của A. Do đó, kiểu ExceptionB mà phiên bản methodA() của B tuyên bố có thể ném phải được định nghĩa là một lớp dẫn xuất từ lớp ExceptionA.

Nếu không có lớp ngoại lệ cơ sẵn nào thích hợp làm lớp cha, ta nên xét đến việc ngoại lệ mới nên thuộc loại check (checked) hay không (unchecked). Còn nếu có thể cho phép chương trình ứng dụng bỏ qua ngoại lệ này, ta chọn lớp cha là RuntimeException.

## 12. CHUỈ HOÁ ĐỐI TƯỢNG VÀ VÀO RA FILE

Các đối tượng có trạng thái và hành vi. Các hành vi lưu trữ trong lớp, còn trạng thái nằm tại từng đối tượng. Vậy chuyện gì xảy ra nếu ta cần lưu trạng thái của một đối tượng? Chẳng hạn, trong một ứng dụng trò chơi, ta cần lưu trạng thái của một ván chơi, rồi khi người chơi quay lại chơi tiếp vẫn còn dở, ta cần nạp lại trạng thái đã lưu. Cách làm truyền thống và là lấy từng giá trị dữ liệu lưu trong mỗi đối tượng, rồi ghi các giá trị đó vào một file theo định dạng mà ta tự quy định. Hoặc theo phương pháp hướng đối tượng, ta chỉ ghi đối tượng, hay ghi dữ liệu, và nhờ con người ghi và phục hồi lại. Cách làm truyền thống có ưu điểm ở chỗ dễ đọc và sửa đổi bằng con người, nhưng khó bảo toàn tính liên kết giữa các đối tượng. Trong khi chuỗi hoá (serialization) cho phép lưu trữ toàn bộ đối tượng và trạng thái của chúng.

Có hai lựa chọn cho việc lưu trữ dữ liệu:
- Nếu file dữ liệu sẽ được dùng bởi chính chương trình đã sinh ra nó, ta dùng phương pháp chuỗi hoá (serialization): chương trình ghi các đối tượng đã được chuỗi hoá vào một file, rồi khi cần thì đọc các đối tượng chuỗi hoá từ file và biến chúng trở lại thành các đối tượng hoạt động trong bộ nhớ heap.
- Nếu file dữ liệu sẽ được sử dụng bởi các chương trình khác, ta dùng file lưu trữ dạng text: Viết một file dạng text với cú pháp mà các chương trình khác có thể hiểu được. Ví dụ, dùng tab để tách giữa các giá trị dữ liệu, dùng dấu xuống dòng để tách giữa các đối tượng.

Tất nhiên, đó không phải là các lựa chọn duy nhất. Ta có thể lưu dữ liệu theo các cách khác nữa. Tuy nhiên, hai cách trên là phổ biến và được dùng nhiều trong thực tế.

Ta có hai lựa chọn cho việc lưu trữ dữ liệu:
- Chuỗi hoá (serialization): ghi đối tượng vào file ở dạng có thể đọc lại được bởi máy, sau đó có thể khôi phục lại đối tượng từ file.
- Ghi dữ liệu ở dạng text (text form): ghi từng trường dữ liệu riêng lẻ vào file văn bản, sau đó đọc lại và dựng lại các đối tượng từ các trường dữ liệu đó.

Hình 12.1: Hai cách ghi đối tượng ra file.

> Lưu ý: Hình minh hoạ ở đây mô tả sự khác nhau giữa ghi đối tượng đã được chuỗi hoá và ghi các trường dữ liệu ở dạng text.

### 12.2. CHUỈ HOÁ ĐỐI TƯỢNG

Chuyện gì xảy ra khi một đối tượng bị chuỗi hoá?
Các đối tượng ở heap có trạng thái là giá trị của các biến thực thể của đối tượng. Các giá trị này tạo nên sự khác biệt giữa các thực thể khác nhau của cùng một lớp. Đối tượng bị chuỗi hoá lưu lại các giá trị của các biến thực thể, để sau này có thể khôi phục lại một đối tượng giống hệt tại heap.

Ví dụ, một đối tượng b kiểu Box có hai biến thực thể thuộc kiểu cơ bản width = 37 và height = 70. Khi gọi lệnh os.writeObject(b), các giá trị đó được lấy ra và bỏ vào dòng, kèm theo một số thông tin khác, chẳng hạn như tên lớp, mà sau này máy ảo Java sẽ cần để khôi phục đối tượng. Tất cả được ghi vào file ở dạng nhị phân.

Đối với các biến thực thể kiểu cơ bản thì chỉ đơn giản như vậy, còn các biến thực thể kiểu tham chiếu đối tượng thì sao? Nếu như một đối tượng có biến thực thể là tham chiếu tới một đối tượng khác, và chính đối tượng đó lại có các biến thực thể, thì toàn bộ chuỗi hoá được thì tất cả các lớp con cháu của nó đều được chuỗi hoá và được tự động chuỗi hoá bởi máy ảo Java khi thực thi.

Khi một đối tượng được chuỗi hoá, tất cả các đối tượng được chuỗi hoá từ các biến thực thể của nó cũng được chuỗi hoá. Và tất cả các đối tượng chuỗi hoá đó sẽ được đóng gói vào một chuỗi dữ liệu nhị phân. Việc đóng gói này sẽ cho phép truyền tải hoặc lưu trữ đối tượng một cách an toàn và dễ dàng hơn.

Đặc biệt, với các đối tượng có trường hợp là tham chiếu tới nhau (các đối tượng tham chiếu tới nhau theo hình chu trình), chuỗi hoá vẫn được thực hiện đúng. Tuy nhiên, để đảm bảo an toàn và tính nhất quán, Java cung cấp cơ chế để đánh dấu các tham chiếu liên quan đến nhau, nhằm giữ cho quá trình khôi phục đúng như ban đầu.

Hình 12.2: Đồ thị tham chiếu của đối tượng ContactList.

Ta đã nói về khái niệm và lý thuyết của việc chuỗi hoá đối tượng. Vậy về mặt thực thi, làm sao để chuỗi hoá và ghi các đối tượng vào file? Người ta sẽ dùng interface Serializable. Nếu một lớp không thuộc loại chuỗi hoá được, chương trình nào gọi phương thức writeObject() cho đối tượng thuộc lớp đó có thể biên dịch không lỗi nhưng sẽ sinh lỗi thời gian chạy (NonSerializableException).

Nếu một lớp không thuộc loại chuỗi hoá được, chương trình nào gọi phương thức writeObject cho đối tượng thuộc lớp đó có thể bị NonSerializableException.

> Ghi chú: Để các lớp có thể chuỗi hoá và ghi được, ta phải đánh dấu (implement) interface Serializable. Các trường không phải là các biến tham chiếu tới các đối tượng khác hoặc các biến tĩnh (static) sẽ được chuỗi hoá. Ngoài ra, nếu một trường không thuộc type chuỗi hoá được, chu trình ghi sẽ bị lỗi tại thời điểm biên dịch hoặc khi thực thi.

### 12.1. QUY TRÌNH GHI ĐỐI TƯỢNG

Cách ghi đối tượng chuỗi hoá sẽ được trình bày một cách chi tiết sau. Tạm thời, ta chỉ giới thiệu các bước cơ bản:

```java
1. Tạo một FileOutputStream – đường dẫn file
   FileOutputStream fileStream = new FileOutputStream("game.dat");

2. Tạo một ObjectOutputStream – đường dẫn được ghi đối tượng
   ObjectOutputStream os = new ObjectOutputStream(fileStream);

3. Ghi các đối tượng
   os.writeObject(zombie);
   os.writeObject(peaShooter);
   os.writeObject(mushroom);

4. Đóng dòng ObjectOutputStream
   os.close()
```

Bước 1 tạo một dòng ra dạng file, FileOutputStream, đối tượng dòng ra này kết nối với file có tên 'game.dat', nếu chưa có file với tên đó thì nó sẽ tạo mới một file như vậy. Bước 2 tạo một đối tượng kiểu ObjectOutputStream – dòng ra cho dữ liệu dạng đối tượng. Nó cho phép ghi đối tượng nhưng nó lại không thể kết nối trực tiếp với một file. Vậy nên ta nối nó với đối tượng dòng ra file để ghi dữ liệu vào file. Bước 3 chuỗi hoá các đối tượng mà zombie, peaShooter, và mushroom ghi tới, rồi ghi nó vào file qua dòng os. Bước 4 đóng dòng ra dạng đối tượng. Khi đóng một dòng ra, dòng mà nó nối tới, ở đây là FileOutputStream, sẽ được đóng tự động. Việc ghi dữ liệu đến đây kết thúc.

Chúng ta đã nói đến các dòng, vậy bản chất chúng là cái gì? Có thể hình dung dòng (stream) như một đường ống mà dữ liệu di chuyển trong đó để từ nơi này sang nơi khác. Thư viện vào ra dữ liệu của Java có các dòng nối tới các nguồn như ổ cứng hoặc mạng, và các dòng nối tiếp (chain stream) không thể kết nối với các đích và nguồn mà chỉ có thể chạy được nếu được nối với các dòng khác.

Thông thường, để làm việc gì đó, ta cần dùng ít nhất hai dòng nối với nhau: một dòng đại diện cho kết nối với nguồn hay đích của dữ liệu, dòng kia cung cấp tiện ích đọc/ghi. Lý do là dòng kết nối thường hỗ trợ ở mức quá thấp. Ví dụ, dòng kết nối FileOutputStream chỉ cung cấp các phương thức ghi byte. Còn ta không muốn ghi từng byte hoặc chuỗi byte. Ta muốn ghi đối tượng, do đó ta cần một dòng nối tiếp ở mức cao hơn, chẳng hạn ObjectOutputStream là dòng nối tiếp cho phép ghi đối tượng.

Vậy tại sao thư viện không có một dòng mà mình nó làm được chính xác những gì ta cần, phía trên thì cho ta phương thức ghi các đối tượng còn phía dưới là chuỗi byte và đồ ra file? Với tư tưởng hướng đối tượng, mỗi lớp chỉ nên làm một nhiệm vụ. FileOutputStream ghi byte ra file, còn ObjectOutputStream biến đổi đối tượng thành dạng dữ liệu có thể ghi được vào một dòng. Thế cho nên, ta tạo một FileOutputStream để có thể ghi ra file, và ta nối một ObjectOutputStream vào đầu kia. Và khi ta gọi writeObject() từ ObjectOutputStream, đối tượng được bôm vào một chuỗi byte.

## 12.3. KHỐI PHỤC ĐỐI TƯỢNG

Như đã nói ở trên, khi lưu một đối tượng, toàn bộ các đối tượng trong đồ thị tham chiếu của nó cũng được lưu. Do đó, tất cả các lớp đó đều phải thuộc loại Serializable. Như trong ví dụ Hình 12.2 thì các lớp ContactList, Contact, PhoneNumber, String đều phải thuộc loại chuỗi hóa được nếu không muốn xảy ra NonSerializableException khi chương trình chạy.

Ta đi đến tình huống khi trong một đối tượng cần lưu lại có một biến thực thể là tham chiếu tới đối tượng thuộc lớp không chuỗi hóa được. Và ta không thể sửa cải đặt lớp để cho nó chuỗi hóa được, chằng hạn khi lớp đó do người khác viết. Giải pháp là khai báo biến thực thể đó với từ khóa transient. Từ khóa này có tác dụng tuyên bố rằng "hãy bỏ qua biến này khi chuỗi hóa".

```
import java.io.*;

public class Box implements Serializable {
    private int height;
    private int width;

    Box(int h, int w) { height = h; width = w; }

    public static void main(String [] args) {
        Box b = new Box(30, 37);

        // các thao tác I/O có thể ném ngoại lệ
        try {
            FileOutputStream fileStream = new FileOutputStream("box.dat");
            ObjectOutputStream os = new ObjectOutputStream(fileStream);
            os.writeObject(b);
            os.close();
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```

Như đã nói ở trên, khi lưu một đối tượng, toàn bộ các đối tượng trong đồ thị tham chiếu của nó cũng được lưu. Do đó, tất cả các lớp được thuộc loại Serializable. Như trong ví dụ Hình 12.2 thì các lớp ContactList, Contact, PhoneNumber, String đều phải thuộc loại chuỗi hóa được nếu không muốn xảy ra NonSerializableException khi chương trình chạy.

Ta đi đến tình huống khi trong một đối tượng cần lưu lại có một biến thực thể là một đối tượng thuộc loại không chuỗi hóa được, và ta muốn đối tượng được chuỗi hóa mà lớp đó lại do người khác viết. Giải pháp là khai báo biến thực thể này với từ khóa transient để bỏ qua khi chuỗi hóa.

## 12.4. GHI CHUỖI KÍ TỰ RA TỆP VĂN BẢN

### 12.4.1. Lớp File

Đối tượng thuộc lớp java.io.File đại diện cho một file hoặc một thư mục. Lớp này không có các tiện ích ghi đọc file, nhưng nó là đại diện an toàn cho file hơn là chuỗi ký tự tên file. Hầu hết các lớp lấy tên file làm tham số cho hàm khởi tạo, chẳng hạn FileWriter hay FileInputStream, cũng cung cấp hàm khởi tạo lấy một đối tượng File. Ta có thể tạo một đối tượng File, kiểm tra xem đường dẫn có hợp lệ hay không, v.v.. rồi chuyển đổi đối tượng File đó cho FileWriter. Với một đối tượng File, ta có thể làm một số việc hữu ích như:

1. Tạo một đối tượng File đại diện cho một file đang tồn tại:
   File f = new File("foo.txt");

2. Tạo một thư mục mới:
   File dir = new File("Books");
   dir.mkdir();

3. Liệt kê nội dung của một thư mục:
   if (dir.isDirectory()) {
       String[] dirContents = dir.list();
       for (int i = 0; i < dirContents; i++)
           System.out.println(dirContents[i]);
   }

4. Lấy đường dẫn tuyệt đối của file hoặc thư mục:
   System.out.println(dir.getAbsolutePath());

5. Xóa file hoặc thư mục (trả về true nếu thành công):
   boolean isDeleted = f.delete();

### 12.4.2. Bộ nhớ đệm

Bộ nhớ đệm (buffer) cho ta một nơi lưu trữ tạm thời để tăng hiệu quả của thao tác đọc/ghi dữ liệu. Cách sử dụng BufferWriter như sau:

```
BufferWriter writer = new BufferWriter(new FileWriter(aFile));

// Sau lệnh trên thì ta chỉ cần làm việc với BufferWriter mà không cần để ý đến đối
// tượng FileWriter nữa.

Lợi ích của việc sử dụng BufferWriter được giải thích như sau: Nếu chỉ dùng
FileWriter, mỗi lần ta yêu cầu FileWriter ghi một chuỗi dữ liệu nào đó, chuỗi đó lập
tức được đổ vào file. Chi phí về thời gian xử lý cho mỗi lần ghi file là rất lớn so với
chi phí cho các thao tác trong bộ nhớ. Khi nối một dòng BufferWriter với một
FileWriter, BufferWriter sẽ giữ những gì ta ghi vào nó để ghi vào đĩa khi bộ nhớ đệm đầy.
Khi bộ nhớ đệm đầy thì FileWriter mới được lệnh ghi dữ liệu ra đĩa. Như vậy,
ta tăng được hiệu quả về mặt thời gian của việc ghi dữ liệu do giảm số lần ghi đĩa
cứng. Nếu ta muốn đổ dữ liệu ra đĩa trước khi bộ nhớ đệm đầy, ta có thể gọi
writer.flush() để lập tức xả toàn bộ nội dung trong bộ nhớ.
```

## 12.5. ĐỌC TỆP VĂN BẢN

## 12.4.1. Lớp File (mở rộng)

Đối tượng thuộc lớp java.io.File đại diện cho một file hoặc một thư mục. Lớp này không có các tiện ích ghi đọc file, nhưng nó là đại diện an toàn cho file hơn là chuỗi ký tự tên file. Hầu hết các lớp lấy tên file làm tham số cho hàm khởi tạo, chẳng hạn như FileWriter hay FileInputStream, cũng cung cấp hàm khởi tạo lấy một đối tượng File. Ta có thể tạo một đối tượng File, kiểm tra xem đường dẫn có hợp lệ hay không, v.v.. rồi chuyển đối tượng File đó cho FileWriter. Với một đối tượng File, ta có thể làm một số việc hữu ích như:

1. Tạo một đối tượng File đại diện cho một file đang tồn tại:
   File f = new File("foo.txt");

2. Tạo một thư mục mới:
   File dir = new File("Books");
   dir.mkdir();

3. Liệt kê nội dung của một thư mục:
   if (dir.isDirectory()) {
       String[] dirContents = dir.list();
       for (int i = 0; i < dirContents; i++)
           System.out.println(dirContents[i]);
   }

4. Lấy đường dẫn tuyệt đối của file hoặc thư mục:
   System.out.println(dir.getAbsolutePath());

5. Xóa file hoặc thư mục (trả về true nếu thành công):
   boolean isDeleted = f.delete();

### 12.4.2. Bộ nhớ đệm (tiếp)

Bộ nhớ đệm (buffer) cho ta một nơi lưu trữ tạm thời để tăng hiệu quả của thao tác đọc/ghi dữ liệu. Cách sử dụng BufferWriter như sau:

BufferWriter writer = new BufferWriter(new FileWriter(aFile));

Sau lệnh trên thì ta chỉ cần làm việc với BufferWriter mà không cần để ý đến đối tượng FileWriter nữa.

Lợi ích của việc sử dụng BufferWriter được giải thích như sau: Nếu chỉ dùng FileWriter, mỗi lần ta yêu cầu FileWriter ghi một chuỗi dữ liệu nào đó, chuỗi đó lập tức được đổ vào file. Chi phí về thời gian xử lý cho mỗi lần ghi file là rất lớn so với chi phí cho các thao tác trong bộ nhớ. Khi nối một dòng BufferWriter với một FileWriter, BufferWriter sẽ giữ những gì ta ghi vào nó rồi ghi vào đĩa khi cần thiết. Như vậy, ta tăng được hiệu quả về mặt thời gian của việc ghi dữ liệu do giảm số lần ghi đĩa cứng. Nếu ta muốn đổ dữ liệu ra đĩa trước khi bộ nhớ đệm đầy, ta có thể gọi writer.flush() để lập tức xả toàn bộ nội dung trong bộ nhớ.

13.5.2. So sánh lớn hơn/nhỏ hơn

Tương tự với so sánh bằng là vấn đề so sánh lớn hơn, nhỏ hơn. Giả sử ta cần một cấu trúc contactList là danh sách các địa chỉ liên lạc – lớp Contact như đã cài ở mục trước, và đôi khi ta cần danh sách đó được sắp xếp theo tên. Có một số cách để làm việc này với các lớp có sẵn trong Collection framework. Ta có thể dùng phương thức sort() đối với danh bạ ở dạng một đối tượng List, hoặc dùng một cấu trúc tự động sắp xếp chẳng hạn như TreeSet để lưu danh bạ. Cả hai cách đều cần phải so sánh hai đối tượng Contact để biết đối tượng nào “lớn hơn” hay “nhỏ hơn”.

1. Các phần tử danh sách phải thuộc một lớp có interface Comparable. Ta sửa lớp Contact để bổ sung phần đúng như trong hình 13.10, chương trình trong hình 13.9, sau đó sẽ chạy không có lỗi.

```java
public class Contact implements Comparable<Contact> {
    String name;
    String address;

    public int compareTo(Contact c) {
        return name.compareTo(c.name);
    }
}
```

![Hình 13.10: Cài interface Comparable.] 

2. Sử dụng phương thức có tham số kiểu Comparator. Ta viết thêm lớp ContactCompare theo interface Comparator và dùng nó trong chương trình TestTreeSet như các dòng in đậm trong hình 13.11. Theo đó, ContactCompare là một loại Comparator được thừa riêng để việc so sánh hai đối tượng Contact được thực hiện theo tên.

```java
class ContactCompare implements Comparator<Contact> {
    public int compare(Contact o1, Contact o2) {
        return o1.name.compareTo(o2.name);
    }
}
public class TestTreeSet {

        tree.add(new Contact("Alice", "Wonderland"));
        tree.add(new Contact("Dumbledore", "Hogward"));
        tree.add(new Contact("Peter Pan", "Neverland"));
        System.out.println(tree);
    }
}
```

13.6. KÍ TỰ ĐẠI DIỆN TRONG KHAI BÁO THAM SỐ KIỂU

Quan hệ thừa kế giữa hai lớp không có ảnh hưởng gì đến quan hệ giữa các cấu trúc tổng quát được dùng cho hai lớp đó. Chẳng hạn, Dog và Cat là các lớp con của Animal, ta có thể đưa các đối tượng Dog và Cat vào một ArrayList<Animal>, và tính chất đa hình giữa Dog, Cat, và Animal vẫn hoạt động như bình thường (xem ví dụ trong Hình 13.12). 13.6.1. Đạo diện và ký tự đại diện

Các ví dụ trên cho thấy cách dùng ký tự đại diện (wildcard) trong khai báo tham số kiểu giúp ta kiểm soát bố cục danh sách và giới hạn kiểu tham chiếu. Tuy nhiên, một số trường hợp sẽ yêu cầu dùng wildcard ở nhiều mức khác nhau để đảm bảo tính an toàn và linh hoạt của dữ liệu.

Ví dụ về khái niệm sau:

```java
public void makeASymphony(ArrayList<? extends Animal> a) {
    for (Animal anAnimal : a) {
        anAnimal.makeNoise();
    }
}
```

```java
public static void main(String[] args) {
    ArrayList<Animal> pets = new ArrayList<Animal>();
    pets.add(new Dog());
    pets.add(new Cat());
    makeASymphony(pets);
}
```

```java
class Animal {
    void makeNoise() {
        System.out.println("Uh oh...");
    }
}
class Cat extends Animal {
    void makeNoise() {
        System.out.println("Meow.");
    }
}
class Dog extends Animal {
    void makeNoise() {
        System.out.println("Grrr.");
    }
}
```

## Phụ lục A. DỊCH CHƯƠNG TRÌNH BẰNG JDK

Phụ lục này hướng dẫn những bước cơ bản nhất trong việc biên dịch và chạy một chương trình Java đơn giản bằng công cụ JDK tại môi trường Windows.

### A.1. Soạn thảo mã nguồn chương trình

Có thể chọn một chương trình soạn thảo văn bản đơn giản, chẳng hạn như Notepad. Hoặc để tiện lợi, ta có thể chọn một chương trình có tính năng tự động hiển thị màu theo cú pháp nhưng vẫn đơn giản, chẳng hạn như Notepad++.

Mã nguồn chương trình cần được lưu vào file có tên trùng tên lớp (chính xác cả chữ hoa và chữ thường) và phần mở rộng .java. Chẳng hạn lớp HelloWorld được lưu trong file có tên HelloWorld.java.

### A.2. Biên dịch mã nguồn thành file .class

Mở một cửa sổ lệnh (console) bằng cách lần lượt chọn Start menu, Run…, rồi gõ lệnh cmd. Cửa sổ hiện ra sẽ có dạng như trong Hình 13.15.

![Hình 13.15: Cửa sổ lệnh]

Tại cửa sổ lệnh, dấu nhắc cho biết thư mục hiện tại. Để dịch file mã nguồn, ta cần thay đổi thư mục hiện tại về thư mục nơi ta đã lưu file đó. Ví dụ, nếu thư mục mã nguồn của ta là C:\java, ta gõ lệnh sau tại dấu nhắc và nhấn Enter:

```
cd C:\java
```

Kết quả là dấu nhắc sẽ chuyển thành `C:\java>`.

Khi gõ lệnh dir tại dấu nhắc, ta sẽ thấy danh sách các file mã nguồn đặt tại thư mục hiện tại như trong Hình 13.16.

![Hình 13.16: Danh sách các file mã nguồn.]

Để dịch chương trình HelloWorld, ta gõ lệnh sau tại dấu nhắc:

```
javac HelloWorld.java
```

Nếu thành công, trình biên dịch sẽ sinh ra một file bytecode có tên HelloWorld.class. Khi dùng lệnh dir lần nữa, ta sẽ thấy file đó được liệt kê trên màn hình như hình dưới đây. Chương trình đã được dịch xong và sẵn sàng chạy.

![Hình 13.17: File .class kết quả của biên dịch.]

Nếu không thành công, ta có thể đã gặp một trong những tình huống sau đây:

1. Lỗi cú pháp: dựa theo thông báo lỗi được trình biên dịch hiển thị ra màn hình, ta cần quay lại trình soạn thảo để sửa lỗi trước khi chạy lệnh javac lần nữa để dịch lại.

```
c:\java> javac HelloWorld.java
```

Hãy đứng yên ở thư mục “gốc” của mình, ví dụ c:\java

Luôn luôn dùng tên đầy đủ của class. Ví dụ:

```
c:\java> java com.mycompanypackage.MyCompanyApp
```

Máy ảo Java biết cách tìm file .class trong thư mục com\mycompanypackage (lưu ý, đây là một quy ước của máy ảo, hầu hết các máy ảo dùng cách này – không có chỗ nào trong đặc tả ngôn ngữ nói rằng gói phải được lưu trữ theo kiểu đó; máy ảo Java đơn giản là phải biết cách tìm và nạp một class).

Đến lúc biên dịch các class. Ta thường biên dịch tất cả các file, để chắc chắn là mình luôn dùng phiên bản mới nhất của tất cả các class. Trong Java có một số sự phụ thuộc không dễ thấy, chẳng hạn như các hàng đổi tương thuộc một class được nhúng trong một class khác (chẳng hạn HandyUtil tham chiếu tới Semaphore.SOME_CONSTANT – một hằng String loại static final, giá trị của nó sẽ được nhúng vào trong HandyUtil.class.) ```


hoặc

```
org\mypersonalpackages\util\*.java
```

Hoặc tạo một danh sách các file và chuyển nó cho javac:

```
c:\java> dir /s /b *.java > srcfiles.txt
c:\java> javac -d . @srcfiles.txt
```

Lưu ý rằng ta biên dịch nó từ thư mục gốc, và ta dùng tùy chọn -d để bảo trình biên dịch xếp các file .class vào một cấu trúc gói xuất phát từ gốc (đầu chấm theo sau có nghĩa là thư mục gốc là thư mục hiện tại). Một số người không thích để các file .class và các file nguồn cùng một chỗ - trong trường hợp đó, ta có thể dùng tùy chọn -d classes, nhưng ta phải tạo thư mục classes từ trước. (Ta cũng sẽ cần hoặc là lần nào cũng dịch tất cả hoặc đặt classes vào phần classpath cho trình biên dịch bằng tùy chọn -classpath.) Nếu chưa thực sự thành thạo, ta nên làm theo cách đầu và kiểm tra.

## Phụ lục B. PACKAGE – TỔ CHỨC GÓI CỦA JAVA

Mỗi lớp trong thư viện Java API thuộc về một gói (package) trong đó chứa một nhóm các lớp có liên quan với nhau. Khi các ứng dụng được viết, ta có thể tổ chức chương trình thành các gói giúp lập trình viên quản lí được các thành phần của ứng dụng. Các gói còn hỗ trợ việc tái sử dụng phần mềm bằng cách cho phép chương trình import lớp từ các gói khác (như ta vẫn làm ở hầu hết các chương trình với ví dụ). Một lợi ích khác của tổ chức gói là cơ chế đặt tên lớp không trùng nhau. Điều này giúp tránh xung đột tên lớp. Phụ lục này giới thiệu cách tạo gói của chính mình.

Các bước khai báo một lớp tái sử dụng được:

1. Khai báo public cho lớp đó. Nếu không, nó sẽ chỉ được sử dụng bởi các lớp trong cùng một gói.
2. Chọn một tên gói và đặt khai báo gói vào đầu file mã nguồn của lớp. Trong mỗi file mã nguồn chỉ có tối đa hai khai báo và nó phải được đặt trước tất cả các lệnh khác. Ví dụ, nếu mã nguồn của ta là com.mycompanypackage.MyCompanyApp, ta có thể đặt khai báo gói ở phía đầu như sau:
   ```
   package com.mycompanypackage;
   ```
   Nếu lớp của ta cần import gì đó từ các gói khác, các dòng import có thể đặt sau đó. Ví dụ, BusinessLogic.java có thể bắt đầu bằng:
   ```
   package com.mycompanypackage;
   import org.mypersonalpackages.util.*;
   ```
   Hoặc:
   ```
   package com.mycompanypackage;
   import org.mypersonalpackages.util.HandyUtil;
   ```
   Một số người thích dùng import-on-demand (các chữ cái đầu) cho các lớp khác nhau, tuy nhiên sẽ có vấn đề khi có hai lớp có cùng tên trong các gói khác nhau.

Thật vậy, nhiều người cho rằng nên dùng các gói để tách các thành phần, vì vậy khi biên dịch sẽ dễ quản lí và hỗ trợ tái sử dụng.

Đến lúc biên dịch các class. Ta thường biên dịch tất cả các file, để chắc chắn là mình luôn dùng phiên bản mới nhất của tất cả các class. Trong Java có một số sự phụ thuộc khó thấy, chẳng hạn như các hàng đổi tương thuộc một class được nhúng trong một class khác (ví dụ HandyUtil tham chiếu tới Semaphore.SOME_CONSTANT - một hằng String loại static final, giá trị của nó sẽ được nhúng vào trong HandyUtil.class.) Có hai cách để biên dịch tất cả. Hoặc là dùng lệnh một cách đúng:

```
c:\java> javac -d . com\mycompanypackage\*.java
```

hoặc tạo một danh sách các file và chuyển nó cho javac:

```
c:\java> dir /s /b *.java > srcfiles.txt
c:\java> javac -d . @srcfiles.txt
```

Lưu ý rằng ta biên dịch nó từ thư mục gốc, và ta dùng tùy chọn -d để bảo trình biên dịch xếp các file .class vào một cấu trúc gói xuất phát từ gốc (đầu chấm theo sau có nghĩa là thư mục gốc là thư mục hiện tại). Một số người không thích để các file .class và các file nguồn cùng một chỗ - trong trường hợp đó, ta có thể dùng tùy chọn -d classes, nhưng ta phải tạo thư mục classes từ trước. (Ta cũng sẽ cần hoặc là lần nào cũng dịch tất cả hoặc đặt classes vào phần classpath cho trình biên dịch bằng tùy chọn -classpath). Nếu chưa thực sự thành thạo, ta nên làm theo cách đầu và kiểm tra.

Chạy ứng dụng

Chúng ta có thể gặp một số tình huống phức tạp khi chạy ứng dụng:

- Lỗi cú pháp: … (nội dung mô tả chi tiết trong tài liệu gốc)
- Thông báo lỗi liên quan đến import hoặc gói, cách sửa…

Ví dụ, để biên dịch và chạy các lớp từ ví dụ ở trên, ta có thể làm như sau:

```
c:\java> javac -d . com\mycompanypackage\*.java
```

```
c:\java> java com.mycompanypackage.MyCompanyApp
```

Hoặc đối với trường hợp phức tạp hơn, ta có thể sử dụng đường dẫn đầy đủ tới đầy đủ của tệp class và toàn bộ gói như đã mô tả ở trên.
